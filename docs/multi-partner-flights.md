# Несколько партнёров: сравнение авиабилетов

Цель владельца (2026-09-25): использовать доступные партнёрские программы и
выбирать выгодные рейсы. Критерий выгоды — цена и условия для путешественника;
размер комиссии HopTrip не входит в рейтинг.

## Что доступно сейчас

| Источник | Получение цен | Статус HopTrip |
| --- | --- | --- |
| Aviasales Data API | Кеш найденных цен; не live-подтверждение | Работает, регулярная загрузка и ссылки |
| Aviasales Search API | Поиск в реальном времени, отдельное одобрение | Не подключён; официальный порог 50 000 MAU |
| Kiwi.com API | Отдельные Locations/Search/Nomad API | Не подключён; официальный порог 50 000 MAU |
| Omio | В списке Travelpayouts указан feed популярных направлений | Не подключён; не считать автоматически источником сравнимых live-цен |
| Прочие программы из кабинета | Зависит от инструментов конкретной программы | Нужны названия, статусы и доступные API/feed |

Проверено по официальным страницам 2026-09-25:
[список API и feeds](https://support.travelpayouts.com/hc/en-us/articles/20384016664594-Brands-that-provide-access-to-APIs-and-data-feeds-for-Travelpayouts-partners),
[Aviasales Search API](https://support.travelpayouts.com/hc/en-us/articles/210995808-How-to-get-access-to-the-Aviasales-Search-API),
[Kiwi API](https://support.travelpayouts.com/hc/en-us/articles/360019237899-Kiwi-com-affiliate-program-API),
[Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).
Открытый список инструментов не подтверждает доступ конкретного аккаунта.
Партнёрская ссылка, виджет и API цен — разные возможности. Drive не поставляет
сопоставимую выдачу всех программ в нашу БД.

## Правила будущего сравнения

1. Сравнивать одинаковые даты, аэропорты, сегменты, пассажиров и класс обслуживания.
   Одинакового названия города и даты недостаточно, чтобы объединить два рейса.
2. Сохранять продавца/источник, его offer ID, исходную валюту и время наблюдения,
   отдельную проверенную ссылку именно этого предложения.
3. Сравнивать полную известную цену с обязательными сборами; багаж, возврат,
   самостоятельная пересадка и длительность должны быть видны отдельно.
   Отсутствующие сведения означают «неизвестно», а не бесплатный багаж/нулевой сбор.
4. Выбор «дешевле» сортирует сопоставимые варианты по полной цене; «удобнее» учитывает
   пересадки и длительность. Не обещать абсолютную минимальную цену по всему рынку.
5. Не склеивать рейсы по неполным данным кеша и не выдавать внешнюю общую поисковую
   ссылку за подтверждение конкретной цены. Статус cached/live сохранять явно.
6. Ошибка одного источника не должна блокировать остальные; отдельные квоты,
   таймауты, свежесть и диагностика нужны для каждого адаптера.

## Следующий этап после подтверждения второго источника

- Зафиксировать разрешённый рынок/канал, контракт API, лимиты, правила кеширования,
  пример ответа и способ получения партнёрской ссылки без секретов в Git.
- Добавить адаптер по реальному контракту и тесты нормализации/ошибок.
- Расширить текущий pipeline (сейчас вызывает только TravelpayoutsDataProvider)
  для независимых запусков источников и отдельного статуса каждого.
- Добавить нормализованные условия тарифа и группу сопоставимых предложений.
  Текущая модель хранит provider-specific offer identity, но полноценного
  сравнения продавцов одного рейса и этих полей ещё нет.
- В интерфейсе показать продавцов, цены и различия, проверить реальные переходы.

Не создавать фиктивные APPROVED-программы и не использовать Aviasales token
для другого поставщика. Статистический API бронирований также не является API цен.

## Расширение маршрутов уже реализовано

Проверенный снимок `apps/api/app/data/destinations.json`: 68 направлений, включая
коды городов MIL/PAR/ROM и связанные аэропорты. Исходные справочники указаны в JSON;
берутся только выбранные сопоставления, без ж/д станций и вертолётных площадок.
Новые направления каталога не означают новые редакционные статьи.

`python -m app.jobs.sync_destinations` показывает результат и откатывает транзакцию;
`--apply` сохраняет. Команда использует общую блокировку pipeline, при конфликте
отменяет весь импорт, не переписывает существующие названия, primary IATA и is_active.
Неизвестные коды по-прежнему пропускаются с диагностикой вместо угадывания города.
