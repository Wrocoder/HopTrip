## Уровни защиты

| Уровень | Что защищает | Инструмент / изоляция |
|---|---|---|
| Backend unit + API integration | Валидация, ingestion, score, freshness, фильтры, ссылки, события, подписки, аналитика и редактор | pytest/TestClient, SQLite fixtures, HTTPX MockTransport/monkeypatch; без live providers/SMTP |
| PostgreSQL integration | Схема, уникальность, advisory locks, concurrency, digest/rehearsal idempotency | pytest marker postgres; только DB hoptrip_test, отдельная схема на тест; перед тестом migration_head применить Alembic |
| Web unit | Даты, деньги, неизвестные значения, presets, i18n, serialization, URL/SEO contracts | Node test runner, `tests/*.test.mjs`; не Playwright |
| Browser E2E | Реальные формы, URL/history, localStorage/cookies, восстановление бюджета и копий, состояния, consent | Playwright `tests/*.spec.ts`, Chrome/Chromium desktop + mobile emulation, local fixture API |
| Дополнительные | SEO/axe/keyboard, сценарии на узких viewport, visual artifacts и операции deploy | scripts/audit-*, *.spec.ts, scripts/tests; не подменяют field metrics и реальные устройства |

Приложение использует один и тот же тестовый каталог для двух JS-runner. `testMatch: '**/*.spec.ts'` теперь отделяет Playwright от `.test.mjs`; иначе unit-модуль с TypeScript require-hook может менять разбор Playwright callbacks.

## Пробелы и правила последующих задач

- F01 теперь имеет автоматическую сигнализацию: ожидаемое падение не засчитывается как PASS; неожиданное исправление ломает тест, пока аннотация не удалена. Падение подготовки до `test.fail` остаётся обычным failure. Задачи DEAL-01/TRIP-01 должны сохранить контекст возврата, не просто удалить проверку.
- Origin preference до AUD-05 не имел найденного отдельного browser-теста полного цикла global search → оба home controls → short-trip submit → reload → clear. Добавлена эта проверка. Наличие других тестов выбора аэропорта не заменяло проверку долговременного cookie.
- Классификация критически неполных itinerary требует явного продуктового контракта (DEAL-04). Сейчас нельзя придумывать expected behavior для несуществующей схемы качества.
- Полный 436-case browser inventory не объявляется пройденным. Остальные specs, WebKit, реальная мобильная клавиатура, screen reader, production marketing mode и live provider/SMTP acceptance остаются отдельными проверками.
- Дополнение SEC-01: consent.spec.ts, alerts.spec.ts и localized-alerts.spec.ts проверены в desktop/mobile (24 cases: 23 pass, 1 unavailable-state failure; desktop signup journey отдельно прошёл). Это закрывает прежний пробел запуска browser alerts, но не подтверждает production delivery и не отменяет исходный failure. Доказательства (`docs/sec01/README.md`; исторический файл удалён).
- Процент строк/ветвей не измерялся. Пустые «тесты наличия файла/копии реализации» не добавлялись. При следующих изменениях выбирать тесты по риску поведения и проверять failure до/после исправления.
