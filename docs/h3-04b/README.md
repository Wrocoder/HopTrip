# H3-04b — понятная сортировка и совместимость

Дата: 2026-11-03. **H3-04b DONE; H3-04 DONE (части a+b).** Объём: порядок каталога, подписи PL/EN/RU/UK, методика, canonical и проверки. Предыдущая H3-04a проверяет достоверность сравнения; её изменения сохранены.

## Решение и контракт

Документируем политику `catalog-order-v2` (версия документа, не новое API-поле): без sort используется **price** — цена перелёта на человека в PLN по возрастанию, затем дата вылета, затем ID. Этот же порядок применяется независимо от наличия медианы: история не является условием для сортировки по цене. «Дешевле» не означает «лучшая поездка» или подтверждённую экономию. Сравнение с историей показывается только по проверенным правилам H3-04a: CURRENT, согласованные цены/медиана, минимум 5 наблюдений. NULL-score в реальной таблице запрещён NOT NULL; дефект PostgreSQL NULL-first не подтверждён.

Явные значения sort=price, sort=departure и sort=score сохраняются. Последний намеренно остаётся совместимым составным индексом с прежней формулой и tie-break, включая legacy/provisional/unavailable объяснения. Его новая подпись — «Cena, historia, świeżość ↓» и переводы. Пояснение прямо предупреждает, что нейтральные баллы при малой выборке могут дать позицию выше проверенного сравнения. Этот режим не выдаётся за ранжирование по подтверждённой скидке. Отдельный сорт по price advantage не добавлен.

API `/api/v1/deals` меняет default на price. `/departures/{code}/deals` и `/destinations/{slug}/deals` используют ту же функцию порядка и получают необязательный sort с теми же тремя значениями; неизвестное значение → 422. Формат ответов прежний, пагинация выполняется в SQL до сериализации, без сортировки загруженной страницы в браузере. Миграций и новых зависимостей нет.

Web всегда отправляет effective default price в API, поэтому при временно старом backend порядок web остаётся явным. Общая константа DEFAULT_SORT используется формой, API-клиентом и canonical. Явные сохранённые sort URLs сохраняют поведение. Ссылки без sort сознательно переходят на новый default. Для сохранения старого порядка нужно sort=score.

SEO: sort=price удаляется из canonical как эквивалент отсутствующего sort, включая пагинацию; sort=score теперь сохраняется и даёт noindex, follow. Пути и locale/hreflang механизм не меняются. Это необходимое изменение эквивалентности URL после смены default, а не переименование страниц. Bookmark/share/affiliate/storage контракты не меняются.

Публичная методика объясняет default/legacy order и существующую валютную политику: импорт только PLN с курсом 1, другие валюты без преобразования не участвуют, EUR approximation не влияет на порядок. Порог 5, формула 60/25/15, время наблюдения/расчёта и ограничения группировки не менялись. Home/landing запросы без sort также получают price; существующие quality gates сохранены.

## Измерение изменения

`test_default_sort.py` создаёт синтетическую пару: 200 PLN с баллом 75 и 600 PLN с баллом 99, обе без подтверждённого объяснения. Прежний явный score возвращает [600, 200], новый default — [200, 600]. Первая показанная цена уменьшается на 400 PLN **только в этом тесте**. Оба объекта сохранены, тот же набор возвращается на двух страницах, все три endpoint согласованы. Это доказательство нового порядка, не измерение эффективности продукта.

Реальное распределение, CTR и uplift не измерялись. Для последующего сравнения использовать непересекающиеся сопоставимые окна H3-18a и SHA выпуска; sort-specific cohort текущая аналитика не собирает, причинный эффект сортировки из общего CTR не выводить. Новая аналитика/consent не добавлялись.
