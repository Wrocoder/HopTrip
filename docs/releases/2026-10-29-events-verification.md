# Дополнительные проверки Ticketmaster — 29 октября 2026

Ветка `test/events-verification-20261029`, база `0f74b27`.
Продуктовая логика событий, расписание и миграции не меняются.
Старое удаление DST-теста не перенесено: действующее ежедневное расписание
и переходы часов продолжают проверяться существующим тестом.

## Изменения

- `scripts/verify-ticketmaster-events.py`: проверяет HTTP-статус публичного API,
  пропускает отсутствующие города и поездки, отклоняет пустой ключ, использует
  настроенный affiliate ID и строгую проверку страниц провайдера. Повреждённый
  ответ не считается успешной пустой выборкой. После сбоя запросы прекращаются,
  отчёт фиксирует остановку, команда завершается кодом 1.
- Путь результата задаётся через `--output`. По умолчанию оба скрипта пишут
  в `.cache`, сохраняя исторические отчёты в docs.
- PowerShell-проверка рынков запрещает HTTP-редиректы. Отчёт явно различает
  проверку publisher host/path и полную валидацию URL адаптером.
- Добавлены 6 Python-тестов без сети и отдельный PowerShell-тест с имитацией
  двух рынков: успешная выборка, 429 с остановкой, отсутствие редиректов и
  отсутствие ключа в отчёте/выводе. Реальные ключи в этих тестах не используются.
- Документ интеграции отделяет актуальное ежедневное расписание/сроки от
  исторического описания исходного выпуска.

группировку, просмотр, совместимость с перелётом и новые проверки скрипта.
Ruff для API и Python-скрипта прошёл. PowerShell: синтаксис и тест сценариев успешны.
