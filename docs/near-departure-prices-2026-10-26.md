# Ближайшие вылеты: срок цены и адресная проверка

Пример владельца: WRO → London, 28–31 октября, HopTrip 452 PLN, Aviasales 661 PLN
за одного пассажира после загрузки (+46,2%). Цена 661 PLN сообщена владельцем;
покупка и доступность у продавца агентом не подтверждались. По одному примеру
нельзя оценить расхождения всего каталога.

## Что установлено

26 октября API HopTrip всё ещё показывал `flight-3630-2026-10-28`, 452 PLN,
наблюдение FIRST_SEEN от `2026-10-25T23:00:06.465451Z`, повторная доставка
`2026-10-26T09:00:06.304866Z`. Проверки доступности не было.
Лимит 48 ч позволял показывать эту запись до 27 октября 23:00 UTC.

В 17:25 UTC с сервера выполнен один адресный запрос Data API:
WRO/LON, departure_at 2026-10-28, return_at 2026-10-31, one_way=false,
market=pl, currency=pln. Ответ HTTP 200, 29 записей. FR 8406 с обратным
вылетом 18:55 UTC и ценой 452 PLN отсутствовал. В ответе есть другие рейсы;
они не являются подтверждением или новой ценой этого же маршрута.
Ключ передавался только в заголовке и не записывался в отчёт.

Поставщик описывает `prices_for_dates` как цены из пользовательских поисков за
последние 48 часов: [Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).
Повтор Data API — проверка кешированного ответа, а не наличия мест у продавца.
Отдельный [Search API](https://support.travelpayouts.com/hc/en-us/articles/210995808-How-to-get-access-to-the-Aviasales-Search-API)
требует отдельного доступа; в проекте настроен Data API, подтверждённого Search API
подключения не найдено. Его [правила](https://support.travelpayouts.com/hc/en-us/articles/34788165535250-Search-API-usage-rules)
требуют пользовательского действия для каждого поиска. Периодический сбор live-результатов
не рассматривается как замена существующему worker кеша.

## Изменено

- Максимальный возраст наблюдения: **6 ч при вылете в ближайшие 7 дней,
  24 ч — в ближайшие 30 дней, 48 ч — дальше**. Более раннее истечение или вылет
  сохраняют приоритет. Вход в более короткое окно учтён в `hidden_after` заранее.
- Одинаковое правило применяется на чтении list/detail/redirect, в генерации,
  очистке и ingestion. Старые записи с прежним expires_at защищены сразу на чтении.
  Повтор доставки той же цены не продлевает наблюдение или срок. История не удаляется.
- API сообщает действующий `max_age_hours`, UI объясняет этот лимит. В открытой
  вкладке ссылка продавца исчезает по дедлайну. Fallback для старого ответа API
  использует то же правило и не зависит от часов браузера при первой отрисовке.
- Добавлен read-only `python -m app.jobs.check_flight_price SLUG`: точные календарные
  даты, исходные маршрут и валюта, сравнение external_id исходного рейса, пагинация.
  Возвращает CACHE_UNCHANGED / CACHE_PRICE_CHANGED / NOT_IN_CACHE_RESPONSE / INCONCLUSIVE.
  Ошибки/неполный ответ не становятся подтверждением отсутствия билета. Команда
  не меняет цену, время наблюдения, историю или статус предложения; всегда
  `live_availability_verified=false`. Токены и URL запросов в ошибках не выводятся.

Предварительный read-only расчёт на БД в 17:37 UTC: из 344 видимых предложений
новое правило оставляет 260; для ближайших 7 дней — 17 из 44. Это срез возраста
наблюдений, не оценка точности цен. Каталог после применения будет короче.

Проверено локально: полный API набор — 537 passed / 7 PostgreSQL skipped;
ruff/mypy успешны. Регрессии покрывают границы, переходы в короткое окно,
старые записи, date-only вылеты, отсутствие redirect/click для просроченных цен,
повтор кеша и обновление изменившейся цены, другой рейс и другую валюту.
Web: 76 unit-тестов, lint и production build с TypeScript успешны.
Браузерные сценарии срока/гидратации: Chromium desktop/mobile — 6 passed,
WebKit mobile — 3 passed. Проверены сроки 24/6 ч и автоотключение ссылки.

## Продолжение 28 октября

Проверены сроки всех 281 актуальных предложений и три исходных билета по
REST/GraphQL. Найдена ошибка команды адресной проверки: другой тариф тех же
рейсов мог перезаписать исходный вариант и дать ложный `CACHE_PRICE_CHANGED`.
Подготовлено сохранение вариантов для диагностики и сопоставление точного
непрозрачного идентификатора билета. Живой поиск Aviasales остановлен CAPTCHA;
итоговые цены продавца пока не подтверждены. [Полный аудит](price-comparison-2026-10-28.md).
