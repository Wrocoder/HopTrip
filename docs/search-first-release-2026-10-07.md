# Поиск и форма на главной — первый выпуск

2026-10-07. Локальная реализация пунктов 1–2 плана улучшений. Не опубликовано.

## Поведение

- На главной есть выбор аэропорта, бюджет в PLN на человека и необязательный
  диапазон дат вылета. Дополнительно можно задать число ночей.
- Главная и каталог используют одну форму и доступные с клавиатуры подсказки
  `Wrocław — WRO`. Выбор работает мышью/касанием и ArrowUp/ArrowDown/Enter/Escape.
- Ввод `WRO`, `wro`, `Wrocław`, `Wroclaw` и пробелы по краям разрешаются в один
  аэропорт. Польские названия и английские алиасы возвращаются самим API.
- Для неоднозначного города, например Warszawa при наличии WAW и WMI,
  требуется выбрать аэропорт. Частичное совпадение не отправляется как готовый выбор.
- После изменения текста выбранный ранее код не используется скрыто.
  Пустое поле означает любое отправление, новый поиск сбрасывает пагинацию.
- API также принимает названия в прямых URL. Неизвестный аэропорт возвращает
  `404 / UNKNOWN_ORIGIN`, неоднозначный — `422 / AMBIGUOUS_ORIGIN`.
  Известный аэропорт без предложений возвращает успешную пустую выдачу.
- Ошибка загрузки справочника не убирает успешно загруженные предложения;
  при недоступности подсказок можно ввести код вручную.
- Длительность подписана в ночах, как фактически фильтрует API (`Deal.nights`).
- Форма помещается вместе с кнопкой в первый экран 390×844 после закрытия
  панели согласия. [Мобильный снимок](search-home-mobile-2026-10-07.png).

## Проверка

Результат: 13 API-тестов, 14 web unit-тестов, 26 Playwright-проверок
(desktop/mobile) прошли. ESLint, Ruff затронутых Python-файлов, Mypy трёх
изменённых Python-модулей и TypeScript прошли; production-сборка web успешна.

API-сценарии используют фиксированную цену 200 PLN: все варианты названия дают
одинаковое предложение при бюджете 200 и пустую выдачу при 199,99. Дополнительно
проверены неизвестные, неоднозначные и неактивные аэропорты, публичные алиасы.

Браузерные сценарии проверяют поиск с главной, прямые URL, редактирование и
очистку аэропорта, сохранение фильтров, пагинацию, неверные даты, выбор мышью
и клавиатурой, axe и ширину 320 px. Существующие проверки каталога, SEO-политики
и перехода к партнёру входят в регрессионный прогон.

Среда: Python 3.12 из SDK проекта; Playwright с установленным Chrome
(`PLAYWRIGHT_CHANNEL=chrome`, `HOPTRIP_TEST_PYTHON` указывает на SDK).

Отдельная проба с полностью отключённым JavaScript в `next dev` осталась на
существующем экране загрузки страницы. Полноценная работа сайта без JavaScript
этим выпуском не заявляется; этот сценарий не входит в успешный браузерный
набор. Серверная обработка названий не зависит от JavaScript и проверена через API.

## Публикация и остаток плана

Нужны обновления API и web; миграции базы не требуются. Сначала API с новым
форматом origin и алиасами, затем web. После публикации повторить поиск WRO /
Wrocław с одним бюджетом и проверить конкретное предложение. Число реальных
результатов может меняться, поэтому сравнивать нужно на одном актуальном срезе.

Выпуски 3–6 (партнёрская локализация, SEO/превью, уведомления, справочные расходы
и жильё) остаются следующими этапами. В рабочей копии сохранены ранее начатые
изменения калькулятора, жилья и событий. JSON покрытия событий не изменён.
