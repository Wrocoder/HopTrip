# Подключение уведомлений HopTrip

## Длительность обновления — развёрнуто 2026-10-02

Сводка на сервере дополнена полями «Длительность», «Начало UTC» и
«Завершение UTC». Обычный запуск использует записанный `duration_ms`, округлённый
до секунды. При повторных попытках показываются общий интервал от начала первой
попытки до успешного завершения (включая ожидание), число попыток и длительность
успешной попытки отдельно. Предварительное обслуживание до первой попытки и
доставка уведомления в эту длительность не входят. Отсутствующая длительность
обозначается «нет данных», а не нулём.

Обновление разрешено владельцем и установлено на сервере; результаты диагностики
описаны в [operations.md](operations.md#сдвиг-расписания--диагностика-2026-10-02).

## Перенос из личного чата в группу

Статус 2026-09-26: перенос выполнен по одноразовой команде владельца. Telegram API
подтвердил тестовую отправку, получатель сохранён; отдельная тема не выбрана.
Проверки activity и monitor после переключения прошли. Инструкция ниже — для будущей смены группы.

Добавьте того же бота в нужную группу и разрешите отправку сообщений. Затем на VM:

```sh
sudo /usr/bin/python3 /opt/hoptrip/scripts/setup-notifications.py --group
```

Скрипт использует уже сохранённый токен и показывает одноразовую команду
`/hoptrip_…@имя_бота`. Отправьте её именно в целевую группу; если включены темы —
в нужную тему. Вернитесь в терминал и нажмите Enter. Команда с @username позволяет
привязать группу без отключения privacy mode бота. Chat ID и ID темы определяются
автоматически. Название группы само по себе не используется для выбора получателя.

Сначала скрипт отправит тестовое сообщение, затем сохранит нового получателя в
`/etc/hoptrip/monitor.env`. При ошибке отправки настройки не меняются. После успеха
новые уведомления о сбоях, обновлениях и письмах поступают в группу вместо личного чата.
Старые письма и уже доставленные сводки не рассылаются заново. Таймеры перечитывают env
при каждом запуске; перезапуск сайта не нужен. Пароли и токен сохраняются без изменений.
Для возврата в личный чат выполните обычный setup без `--group`; ID темы будет очищен.

## Первичное подключение

В Windows PowerShell подключитесь к серверу:

```powershell
ssh -i "$env:USERPROFILE\.ssh\domarion_oci_staging_ed25519" ubuntu@141.144.246.78
```

Дальше команды выполняются на сервере.

1. Подключите бота:

   ```sh
   sudo /usr/bin/python3 /opt/hoptrip/scripts/setup-notifications.py
   ```

   Вставьте токен: символы не отображаются. Откройте указанного бота в личном чате,
   нажмите Start, отправьте показанный код `hoptrip-…`, затем Enter в терминале.
   Chat ID определяется автоматически. Используйте отдельного бота без webhook.

2. Подключите входящие письма:

   ```sh
   sudo /usr/bin/python3 /opt/hoptrip/scripts/setup-notifications.py --mail
   ```

   Enter выбирает `kontakt@hoptrip.pl`. Введите пароль этого ящика Zimbra (скрытый ввод).
   Скрипт проверяет вход через `imap.mail.ovh.net:993` с TLS, затем сохраняет данные.
   SMTP не требуется. Инструкция OVH: https://docs.ovhcloud.com/en/guides/web-cloud/email-and-collaborative-solutions/zimbra/mail-apps

3. Проверьте доставку и задайте исходную точку для почты:

   ```sh
   sudo systemd-run --wait --pipe --collect --property=EnvironmentFile=/etc/hoptrip/monitor.env /usr/bin/python3 /opt/hoptrip/scripts/monitor.py --test-alert
   sudo systemctl start hoptrip-activity.service
   ```

   В Telegram должно прийти тестовое сообщение и сводка последнего обновления данных.
   Затем отправьте новое письмо на `kontakt@hoptrip.pl`: уведомление ожидается примерно
   в течение минуты. Старые письма при подключении не рассылаются.

Таймеры уже включены: события/почта каждую минуту, проверки сайта/backup/pipeline каждые
5 минут. Ошибки и восстановление отправляются отдельно. Для проверки без секретов:

```sh
sudo systemctl list-timers 'hoptrip-*'
sudo journalctl -u hoptrip-activity.service -u hoptrip-monitor.service -n 20 --no-pager
```

Токен и пароль хранятся только в `/etc/hoptrip/monitor.env`, доступ root 600.
Не присылайте этот файл, токен или пароль в чат. Скрипт сохраняет остальные настройки.
При падении всей VM этот монитор не сможет отправить уведомление: внешний мониторинг
остаётся отдельной задачей.
