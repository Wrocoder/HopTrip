# H3-12c — редактор сохранённого плана по ID

2026-11-04. Реализация оставшегося lifecycle H3-12 после privacy12a и store12b. В этой части не выполняются H3-13/15/17/18 и не включаются уведомления14. PR/commit не создавались.

## Что найдено и изменено

Storage v2 уже умел UUID/revisions, Update/Duplicate/delete/undo с Web Lock,20limit и explicit legacy migration. Но UI продолжал открывать token snapshots и Save создавал другую запись при правке. [Baseline1/1](baseline.json) воспроизвёл два ID после Save→edit→Save, отсутствие Update и token-based Saved link.

Теперь Save открывает `/trip#local=<UUID>`; v2 карточки ведут по постоянному ID. `Update` меняет существующий plan с expectedRevision, `Duplicate` создаёт отдельный ID даже при одинаковых значениях, Delete/Undo работают по ID/revision. При no-op Update кнопка disabled. Изменение budget/dates/events/profiles не добавляет запись само: список меняется только явным действием. Share остаётся переносимой независимой v1 копией `/trip#plan=<token>` без ID и local revision. Legacy `?plan=` и старые fragment snapshots продолжают работать; до12b migration старые карточки остаются snapshots/read-only как прежде.

UI4locale различает saved/dirty/conflict/deleted, pending/error/full/corrupt/no-lock; есть явное «Отменить правки и загрузить сохранённое». При записи snapshot фиксируется в момент клика. Если пользователь продолжает ввод или сбрасывает калькулятор, успешный commit продвигает только base revision **текущего** рабочего draft, сохраняя поздние правки; они остаются dirty. Поздний NBP callback по прежнему saveIfCurrent guard не перезаписывает изменённый draft. Удаление в другой вкладке не воскрешает ID через Update; открытые правки можно дублировать или отправить ссылкой.

Смена каталожной цены/дат показана отдельно от entered budget; live offer lookup передаёт только public slug. Missing/API error/expired offer не стирает plan и не блокирует ручной бюджет. Existing offerDeadline/useOfferExpired переиспользованы для stale/current-expired metadata, прежний UTC date-only past-date fallback сохранён. Каталожный schedule и saved offer metadata не заменяют даты проживания; автоматического переноса текущей цены в пользовательские суммы нет.

## Локальные данные и совместимость

| Данные | Правило |
|---|---|
| Committed collection | Прежний `hoptrip.saved-plans.v2`, UUID/revisions/20limit/700000 container guard. Schema/writer/Web Locks не менялись, DB migration/dependencies нет |
| Working ID draft | `sessionStorage[hoptrip.plan-draft.v1:<id>]`, тот же BudgetDraft v1. Изолирован по вкладкам, переживает reload/возврат/язык в этой вкладке. Закрытие вкладки удаляет **неподтверждённые** правки; UI это сообщает. Нажатие Update сохраняет в browser-local collection |
| Base revision | В прежнем opaque draft.context: `{input,start,end,plan:{id,revision}}`. Структура BudgetDraft/shared v1 не меняется. encodeTrip как прежде очищает context; UUID/baseRevision не попадают в Share |
| Recovery seed | Session `:seed`, bounded7000chars SavedPlan. Даёт сохранить рабочую копию через Duplicate/Share после удаления исходного ID в другой вкладке и reload; authoritative committed state всегда читается из v2 |
| Legacy drafts | Старые per-offer/per-copy localStorage keys не удаляются и не переписываются этим переходом. Если ID draft отсутствует, может быть восстановлен прежний copy draft по **точному** saved token, с current base revision и статусом dirty при отличии значений. Источник остаётся; discard текущего ID draft не удаляет другие copy drafts |
| Share / SEO | Прежние v1 payload/6000limit, generic private metadata/noindex/no-referrer/canonical/4locale URLs. Local ID link привязан к устройству/профилю, другой браузер получает ясное missing-local сообщение; переносить нужно Share |

Открытие/lookup/storage events не обновляют поля активного editor: snapshot seed заморожен, а текущая revision сравнивается отдельно. Другая вкладка не перезаписывает session draft. После explicit reload saved version snapshot/base обновляются; при storage failure локальные правки остаются. Corrupt/unreadable collection не выдаётся за подтверждённое удаление или успешный save, mutations fail closed, Share рабочей копии доступен. Session recovery metadata тоже не является подтверждением live price/booking.

Dirty comparison считает legacy absent adultsOnly эквивалентным false, **не** переписывая исходный token при открытии. [Compatibility probe](v1-compatibility.json) проверяет прежние v1 bytes/paths, удаление opaque binding из shares, unchanged v2 schema, stable update ID и независимость оригинальной ссылки. Adult-only source/assumptions/manual0/unknown/person-group/integer grosz и currency/reference provenance сохранены. Новых cloud permissions/аккаунтов/API endpoints/analytics events/affiliate parameters нет. TRIP_SAVE остаётся созданием, Update не имитирует новый save event; taxonomy extension остаётся18b.

## Rollback и следующий шаг

Без feature flag. Сохранить v2 collection/12b backup и12a portable readers. Откат generator/list links к portable snapshots возможен, но уже выданные `#local=` bookmarks требуют оставить local reader. ID session drafts не удалять: старый editor их не читает, поэтому оставить read-only recovery или explicit export. Не заменять общие файлы целиком изHEAD; вернуть только12c delta, сохранив прошлые H3/пользовательские изменения. Не мигрировать v2 обратно в старый token array автоматически.

Known first-price/CLS и RU/UK desktop CTA clipping920.14px>900 с before/after delta0 из12b остаются17b; причина transient cross-tab11a не объявляется установленной. Дальнейшая самостоятельная задача — **H3-13**, используя существующий event-fit classifier. Здесь остановка до её начала.
