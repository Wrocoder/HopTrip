Дата: 2026-11-07, Europe/Warsaw. **DONE локально.** Проверена текущая рабочая копия после V4-04. [Инвентаризация](inventory.json), [результаты проверок](verification.json), [контактный лист добавленных направлений](contact-sheet.png).

## Результат аудита и изменения

В репозитории уже были центральный `destination-imagery.ts`, локальные WebP, четыре языка alt/copy, credits, адаптивный `next/image`, lazy loading и fallback при ошибке. Переписывать эту систему не потребовалось.

Найден пробел: проверенные фотографии Wrocław, Warsaw, Kraków, Gdańsk, Katowice, Poznań, Bergen и Reykjavík уже поставлялись со статьями, но не были доступны карточкам соответствующих направлений. Восемь точных соответствий добавлены в существующий реестр. Для Bergen используется фотография Bryggen из статьи о Норвегии, для Reykjavík — городской вид из статьи об Исландии; фотографии ледников не назначаются городам. Источник, автор, лицензия, ShareAlike, дополнительная атрибуция и подписи PL/EN/RU/UK переиспользуются без изменений.

В тип изображения добавлены обязательные width/height. Для трёх старых destination assets записаны фактические 960×600; для фотографий статей сохраняются 1200×750. Компонент карточки использует эти значения вместо одинаковых 960×600 для всех файлов. Соотношение сторон остаётся 8:5; `sizes`, `srcset`, lazy loading и существующий дизайн сохранены.

## Отказы и загрузка

Существующий fallback подтверждён для HTTP 404, сетевого отказа и HTTP 200 с недекодируемым содержимым. После ошибки элемент img удаляется, остаются локализованное сообщение, frame 8:5, credit и ссылка направления. Размер frame до/после одинаков; ссылка доступна мышью и клавиатурой, resize не запускает загрузку изображения заново. У неизвестного направления на главной нет пустой фотокарточки или сообщения о технической ошибке.

Destination photos загружаются lazy; `next/image` выдаёт responsive srcset. Для article cover сохранён существующий preload там, где это нужно над первым экраном; inline и отложенные cover остаются lazy. Нет новых CDN, runtime обращений к фотохостингам, новых bitmap-файлов или зависимостей.

- Полная инвентаризация дополнительно проверила декодирование пикселей, хеши, размеры, отсутствие EXIF/XMP и on-disk attribution всех 34 файлов. В первом browser-прогоне четыре проверки предполагали ровно один запрос при ошибке. В установленном Next Image есть повторное назначение `src` при гидратации для доставки ранее случившегося native error (`next/dist/client/image-component.js`). Тест уточнён: после появления fallback и нескольких resize число запросов должно оставаться неизменным. Это исправление тестового предположения, а не дефект загрузки приложения; повтор прошёл.

`next-env.d.ts` восстановлен до состояния перед задачей; локальные серверы после Playwright завершились. Прочие изменения рабочей копии сохранены.
