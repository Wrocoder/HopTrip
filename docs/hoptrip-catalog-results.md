# HT-08 — выдача: количество, сортировка и состояния

Локальная реализация, 2026-10-11.

## API и совместимость

GET /api/v1/deals по умолчанию по-прежнему возвращает массив.
Параметр include_total=true возвращает объект:
items, total, offset, limit. /deals/{slug} и посадочные страницы сохраняют контракт.

Все фильтры, видимость, статус и свежесть применяются к общей CTE.
Количество и страница выбираются одним SQL-запросом, из одного снимка данных.
LEFT JOIN оставляет строку с total даже при пустой странице.
Ограничение/смещение применяются после сортировки; сериализация карточек прежняя.

| sort | Порядок |
| --- | --- |
| score (по умолчанию) | deal_score DESC, trip_start ASC, id ASC |
| price | price_per_person_pln ASC, trip_start ASC, id ASC |
| departure | trip_start ASC, price_per_person_pln ASC, id ASC |

Неизвестный sort возвращает 422. Формула оценки не менялась.
ID делает равные значения устойчивыми. Между отдельными запросами страницы
живой каталог может обновиться: фиксация пользовательского снимка на всю
сессию не входит в задачу.

Сохранены пределы API: limit 1–100, offset 0–10000. Web использует страницы
по 12 записей, не показывает «следующую» после последнего результата.
При достижении предела offset и наличии дальнейших результатов предлагает
сузить фильтры. Общее количество при этом остаётся полным.

## Интерфейс

URL хранит sort вместе с фильтрами и offset. Смена сортировки, отправка
изменённых фильтров, пресеты и снятие фильтра сбрасывают offset.
Снятие отдельного/всех фильтров сохраняет sort. Сортировка применяет также
введённые значения формы после её валидации.
Повторное открытие, reload и история восстанавливают значения из URL.

Показаны общий total и диапазон текущей страницы.
При total>0 и пустой странице предложен переход на первую с сохранением фильтров.
При total=0 предложено явное снятие конкретного ограничения: цены, выходных,
ночей, дат, направления или аэропорта; автоматического изменения нет.
Предложение расширить поиск не обещает появления результатов.

Загрузка — loading.tsx и Suspense с ключом параметров, включая переходы
между фильтрами. Некорректные параметры показывают отдельную ошибку.
Недоступность каталога показывает сообщение и повторный запрос, без фиктивного
нулевого счётчика. Ошибка доступа к каталогу не означает проверенную ошибку
внешнего авиапоставщика: источник здесь — API сохранённых предложений.

SEARCH_RESULT.result_count остаётся количеством на показанной странице согласно
контракту HT-04. Новый общий total — число в UI/API; определение аналитики
и её allowlist не расширялись.

## Проверка

API: test_catalog_results.py плюс прежние catalog/trip_filters/destination_search.
Проверяются равные ключи, четыре последовательные страницы, независимые
сортировки, фильтры, скрытые/просроченные записи, пустой результат, offset
за концом, неверный sort и прежний массив.

Web: catalog-results.spec.ts плюс catalog, trip-filters, funnel-analytics.
Проверяются total/диапазон, сортировка/URL/история/reload, сброс страницы,
снятие ограничения и отдельные состояния загрузки/ошибок на desktop/mobile.
Для SSR только в изолированном e2e_app предусмотрены budget=987654 (задержка)
и budget=987653 (503). В production этих сценариев нет.
Скриншоты выдачи: test-results/catalog-results-*/catalog-results.png.

Ограничение среды: тесты БД выполнялись на SQLite. TEST_DATABASE_URL для
изолированного PostgreSQL не настроен; выполнение на PostgreSQL в этом запуске
не проверено. Миграция не нужна. Production и внешние партнёры не затрагивались.
