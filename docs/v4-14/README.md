## F01 — неточное направление в пустом списке

Наблюдение: страница /saved советовала открыть оферту и выбрать сохранение «при калькуляторе» во всех четырёх языках. После V4-07 действия находятся в отдельной секции, доступной через пункт «Сохранить и поделиться». Это конкретное несоответствие инструкции текущей структуре, а не предположение о поведении участников.

До изменения PL production-проверка воспроизвела отсутствие корректного навигационного названия в подсказке — [browser-before.json](browser-before.json). Исходный словарь подтверждал аналогичную инструкцию EN/RU/UK. Исправлено только направление подсказки: название берётся из существующего tripSectionCopy, а кнопка/сохранение/хранилище не меняются. PL/EN/RU/UK используют одну вставку {section}, чтобы будущая смена названия навигации не оставила устаревшую копию.

Метрика: подсказки, называющие существующий пункт навигации с переходом к секции реальной кнопки, **0/4 → 4/4**. До — исходный словарь и PL browser; после — полный пользовательский путь в четырёх языках на desktop/mobile. Это измерение точности текста, не доказанное сокращение действий или времени.

Новый usability-guidance.spec.ts открывает пустой список, следует по ссылке поиска, открывает реальную карточку, нажимает указанный пункт навигации, проверяет anchor/focus/кнопку, сохраняет и снова открывает план из списка. В финале axe main без нарушений. [Восемь записей evidence](guidance-evidence.json).
