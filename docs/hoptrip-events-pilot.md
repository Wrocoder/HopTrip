# HT-21: решение по источнику событий для Милана

Проверено 2026-10-12. Исследование завершено; публичный пилот пока **NO-GO**.
Ticketmaster Discovery технически подходит для ограниченной афиши Милана:
исторический собственный доступ и реальные записи подтверждены. Актуальность
доступа сегодня и допустимость коммерческого использования HopTrip не подтверждены.
Поэтому HT-22 остаётся BLOCKED. Подтверждение Stay22 к Ticketmaster не относится.

## Почему Милан

Публичный HopTrip API прочитан 2026-10-12 в 18:57 UTC: три последовательные
страницы limit=100, offset=0/100/200, 249 уникальных оферт, из них 70 — Milan
(28,1%). Это самый представленный город: далее Oslo 16, Malta 15, Rome 14.
Лимит проверки 1000 записей не достигнут, дублей ID нет. Пагинация не является
транзакционным снимком: между запросами выдача может обновиться.
[Снимок с датами и расписанием](hoptrip-events-city-snapshot.json).

Например, `flight-2293-2026-10-14`: KTW → BGY, 14–18 октября, четыре ночи.
В сохранённых flight_facts прибытие 14 октября 05:35Z (07:35 Europe/Rome),
обратный вылет 18 октября 21:55+02:00. Это наблюдаемое расписание, которое
пользователь перепроверяет у продавца. BGY — аэропорт поездки в Милан, но
события Бергамо автоматически к Милану не относятся.

## Какие реальные данные уже получены

[Проверка собственного ключа 30 сентября](events-provider-access.md) и
[машиночитаемый отчёт](events-coverage-2026-09-30.json) сохранены ранее.
Прямой запрос на 14–15 октября вернул пять уникальных записей, API total=5,
из них одну музыкальную и ни одной Sports. Примеры из того ответа:

| ID | Событие | Локальное начало | Площадка |
| --- | --- | --- | --- |
| Z59rmIYnyZ16v | FABIO DE LUIGI — BIOL | 14 октября 21:00 | Teatro Lirico Giorgio Gaber |
| Zf98xZKrZekv6eZup5QQKr | Jack Savoretti | 15 октября 21:00 | Fabrique |
| ZG9rmIYnyZ7Aa6 | MARTIN PARR — Open Ticket Weekend e Festivi | 15 октября 10:00 | Spazio Varesina 204 |

Часовой пояс примеров — Europe/Rome; исходные ссылки есть в JSON. Это исторические
наблюдения, а не сегодняшнее подтверждение статуса, точного времени или билетов.
Полный сырой ответ не сохранён: отсутствующие в отчёте флаги не восстанавливались.
Попытка открыть страницу Jack Savoretti 12 октября через web-инструмент дала
только iframe, поэтому повторной проверкой события она не считается.

Широкая историческая выборка Милана: 144 уникальные записи из заявленных 153,
выгрузка неполная. У 144 есть поле времени и часовой пояс, у 0 — priceRanges.
Само наличие времени не доказывает timeTBA=false. Классификации содержали
109 Music, 8 Sports, 23 Arts & Theatre, но такие счётчики могут повторяться
на одной записи. 79/80 исторических поездок имели календарное пересечение;
это не доля сегодняшних 70 поездок и не проверка возможности успеть.
Open-ticket выходного дня с датой четверга особенно требует проверки правил билета.

В этом запуске новый запрос Discovery не выполнен: ключа нет в окружении
TICKETMASTER*, известных локальных .env и рекомендованном файле
`~/.hoptrip/ticketmaster-api-key.txt`. Старый журнал подтверждает предоставление
ключа, но не сохраняет фактический путь. Путь запрошен у владельца; секрет
не требуется отправлять в чат. Исторический ответ не выдан за новый.

## Официальная документация, повторно прочитанная 12 октября

[Discovery v2](https://developer.ticketmaster.com/products-and-docs/apis/discovery-api/v2/):
ключ в apikey; 5000 запросов/день, 5/с; глубокая пагинация size × page < 1000.
Есть фильтры city/countryCode и localStartEndDateTime для пересечения периодов.

Пример структуры — **карта документированных полей, не искусственный API-ответ**:

| Поле | Значение для адаптера |
| --- | --- |
| _embedded.events[].id, name, url | Идентификатор, название, первоисточник |
| dates.start.localDate/localTime/dateTime | Локальное начало и момент времени |
| dates.start.dateTBD/dateTBA/timeTBA/noSpecificTime | Неопределённость даты/часов |
| dates.end.localDate, spanMultipleDays | Конец и многодневность |
| dates.timezone | Часовой пояс события |
| dates.status.code | onsale, offsale, canceled, postponed, rescheduled |
| _embedded.venues[] | Площадка, город, страна, timezone |
| classifications[], priceRanges[] | Категория, необязательный диапазон цены |
| page.totalElements/totalPages/number/size | Полнота и пагинация |

[FAQ](https://developer.ticketmaster.com/support/faq/) указывает 2/с при тех же
5000/день. До уточнения лимитов аккаунта использовать максимум 1/с,
останавливаться при 429 и учитывать ответные заголовки квоты. Affiliate требует
отдельного одобрения и Impact Publisher ID; работающий ключ не подтверждает комиссию.

[API Terms](https://developer.ticketmaster.com/support/terms-of-use/), дата редакции
27 июня 2023: ограничения получения дохода через API, хранение только разумный
срок, удаление по требованию в течение 24 часов. Численный TTL не указан.
Практическое решение проекта — дождаться письменного подтверждения сценария
HopTrip с существующими партнёрскими ссылками и условий кеширования/отображения.
Заявка 30 сентября и напоминание 5 октября зафиксированы в журнале;
ответа в доступных материалах нет. Почтовый ящик в рамках этой проверки не читался.

## Контракт будущего пилота

Это проектные решения HopTrip, а не обещания поставщика:

1. Явное соответствие `destination_slug=milan` → Milan/Milano, IT,
   Europe/Rome. Повторная проверка площадки после API-фильтра; без расширения
   на соседние города и без географии, произвольно передаваемой клиентом.
2. Запрос только на выбранные даты поездки; локальная проверка пересечения.
   Для one-way нужен явный конец пребывания. Для многодневного билета проверять
   условия конкретных сеансов, а не считать весь период непрерывным доступом.
3. Исключать canceled/postponed и неопределённые даты. rescheduled принимать
   только с определённой новой датой в поездке, с заметной подписью переноса.
   offsale показывать как отсутствие продажи; onsale не гарантирует билет.
4. При известных часах исключать явно несовместимые начала; учитывать конец
   события при наличии. В дни перелётов отдельно предупреждать о трансфере,
   регистрации и неизвестной длительности. Время доезда BGY → площадка не получено,
   поэтому даже начало после посадки не гарантирует, что пользователь успеет.
5. Дедупликация по provider/id, отдельные сеансы сохраняют свои ссылки/цены.
   Не объединять разные билеты только по названию. Arts & Theatre не равнозначно
   выставкам; полноту музыки/спорта/выставок не обещать.
6. Предложенный бюджет проверки: две страницы по 100, максимум 1 запрос/с.
   При усечении явно partial; пустота означает отсутствие данных источника.
   Для пилота предложен кеш 15 минут, checked_at — время получения ответа,
   не проверки покупки; TTL требует согласования, после истечения не выдавать
   старые статусы за свежие. Ошибка источника не ломает страницу перелёта.

В `feature/ticketmaster` уже есть адаптер и UI четырёх городов
([старый отчёт](events-implementation.md)). В HT-21 ветка не переносилась,
тесты старого адаптера заново не запускались. Перед HT-22 её нужно сопоставить
с текущим расписанием flight_facts и ограничить одним выбранным городом.

## Как снять блокер HT-22

- Получить путь к собственному ключу и выполнить свежий ограниченный запрос
  на 14–18 октября для текущей оферты либо на другие ещё актуальные даты.
  Сохранить только разрешённые поля и агрегаты, без apikey/полного URL запроса.
- Зафиксировать HTTP-результат, пагинацию, статусы, определённость времени,
  площадки, долю цен и реальные подходящие записи. При 401/403/429 остановиться;
  отсутствие ответа не подменять фикстурой.
- Добавить ответ Ticketmaster о разрешённом сценарии, контенте и хранении.
  Затем принять отдельное решение GO и перейти к HT-22.

Файлы этого этапа: этот отчёт, снимок текущих оферт, журнал задач.
Проверены JSON, число уникальных записей, выбор города, исторические примеры
и официальные документы. Код приложения и production не изменялись.
