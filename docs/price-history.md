# История цен

Offer identity: provider + external_id. Для v3 external_id — hash маршрута, дат,
авиакомпании, номера рейса и пересадок. Цена не входит в identity предложения.
Observation identity: provider + external_id + нормализованная цена/валюта +
source_observed_at, если источник действительно его сообщил.

Повторная доставка не создаёт независимое наблюдение. Новое source timestamp
с прежней ценой создаёт новую запись. Если timestamp отсутствует, повтор той же
цены сохраняет первое время наблюдения; мы не можем доказать независимость.
История поэтому консервативна и не равнозначна количеству поисков пользователей.

fetched_at — доставка, source_observed_at — сообщение источника, last_verified_at —
консервативный момент наблюдения, не live-подтверждение продавцом.
TTL максимум 48 часов, меньший expires_at источника имеет приоритет. Date-only вылет
закрывается в начале указанного UTC-дня. Публичные list/detail/redirect дополнительно
проверяют статус, видимость, TTL и вылет даже при остановленном worker.

Миграция 0013 ничего не удаляет. Перед обновлением существующей БД выполнить
python -m app.jobs.preflight. При дублях exit 2 и JSON с ключами групп:
сначала backup, затем отдельное решение о canonical записи и сохранении всех
ссылок/истории. Автоматическое удаление дублей намеренно не выполняется.
Безопасный fallback заменил отклонённый автоматической проверкой вариант очистки.

## Актуальность цены — 25 октября 2026, локальная реализация

Наблюдение цены, доставка записи и проверка доступности — разные события.
`DealRead.price_freshness` сообщает `observed_at`, `observation_basis` (`SOURCE`,
`FIRST_SEEN` или неизвестно), `fetched_at`, `hidden_after` и `max_age_hours`.
`availability_checked_at` сейчас всегда `null`: загрузка кеша не проверяет остаток
билетов у продавца. Старое имя `last_verified_at` сохраняется для совместимости API,
но не показывается как live-проверка. Происхождение не переносится с уже изменённого
TravelOffer на цену старого снимка Deal. Для старых записей неизвестные поля не выдумываются.

Повтор того же observation_key сохраняет время первого наблюдения и наиболее ранний
из уже известных сроков истечения. Отсутствующий или более поздний `expires_at` в повторной
доставке не возобновляет старое предложение. Независимое новое наблюдение источника
может обновить цену и срок; запоздавшее старое наблюдение не заменяет новую цену.

Единое правило каталога: возраст наблюдения строго меньше 48 часов, срок истечения
ещё не наступил, вылет ещё впереди. На точной границе 48 часов предложение уже скрыто.
Наблюдения из будущего не публикуются. Ограничения применяются при чтении списка,
деталей и `/go` независимо от worker; дополнительно проверяется связанный TravelOffer,
даже если снимок Deal ещё не пересоздан. Worker переводит снимки в `STALE`/`EXPIRED`.
Историю и сохранённые планы не удаляем. `hidden_after` — срок показа в каталоге,
не обещание сохранения цены или наличия билетов до этого момента.

Рядом с ценой в каталоге и деталях постоянно видны время наблюдения по Варшаве
и пояснение об окончательной цене у партнёра. В деталях отдельно доступны время
доставки записи и срок скрытия; повторная доставка прямо названа не новой проверкой.
В открытой вкладке при истечении срока появляется предупреждение, ссылка к партнёру
заменяется обновлением страницы; при возврате в фоновую вкладку срок перепроверяется.
Старые ответы API поддерживаются без приписывания времени загрузки неизвестным данным.
Тексты доступны на PL/EN/RU/UK, формат сохранённых ссылок на планы не менялся.

Источник — кеш поисков, что отдельно описано в
[официальной документации Aviasales Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).
Наш лимит показа 48 часов не заменяет реальную проверку тарифа.

Aviasales 200. Путь поиска, PLN и ожидаемая кешированная цена сохранены.
