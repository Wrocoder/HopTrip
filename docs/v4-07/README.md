# V4-07 — четыре раздела страницы поездки

Выполнение 2026-11-08. Зависимости V4-06 и V4-08 завершены; работа ограничена V4-07. Проверялась текущая рабочая копия со всеми прежними изменениями.

## Что изменено

На странице предложения, в полученной копии и в редакторе сохранённого плана используется одна навигация из четырёх пунктов:

| Раздел | Якорь | Содержимое |
|---|---|---|
| Перелёт и бронирование | `#trip-flight` | Цена и её актуальность, расписание и предупреждения, переход к партнёру; сравнение с историей находится здесь же |
| Жильё и занятия | `#trip-stay` | Проживание, доступные занятия, события и путеводители; на копии — прежние инструменты проживания и событий |
| Бюджет всей поездки | `#calculator` | Начальный и подробный расчёт V4-08, известные/неизвестные расходы, профили, источники и события плана |
| Сохранить и поделиться | `#trip-save` | Прежние сохранение, обновление, копирование, удаление/восстановление и отправка независимой копии |

Вместо прежних максимум восьми пунктов навигации теперь всегда четыре. Калькулятор и сохранение выводятся соседними секциями, используя тот же `draft`, `ready` и `TripDraftProvider`. Второй store или копия состояния не создаются; схемы сохранённых/общих планов не менялись. На самостоятельных страницах калькулятора сохраняется прежний режим вывода.

Сравнение цены перенесено из конца страницы в раздел перелёта. Подробный расчёт исторического индекса остаётся в существующем disclosure. Предупреждения о качестве данных, расписании и пересадках не переносились в сворачиваемые блоки. Условия о жилье и багаже объединены в один абзац с сохранением текста; в копии плана убрана повторная инструкция редактировать калькулятор ниже.

Старые `#trip-booking`, `#accommodation`, `#destination-activities`, `#trip-events`, `#score`, `#calculator` и `#trip-save` сохранены на прежних инструментах. Переходы по четырём основным разделам доступны с клавиатуры. Существующая обработка fragment payload продолжает сохранять `plan`/`local`, `section`, reload и историю браузера; её код не менялся.

Для недоступной, истёкшей или ещё проверяемой сохранённой оферты `#trip-stay` существует постоянно. Он показывает состояние вместо исчезающего пункта меню; уже введённые расходы и события сохраняются в бюджете. Платные ссылки или данные о наличии не создаются из сохранённого снимка.

Вручную просмотрены [страница при 320 px](detail-ru-320.png), [1440 px](detail-ru-1440.png) и [отдельное сохранение при 320 px](save-editor-320.png). [Критические предупреждения](critical-warnings.png) остаются снаружи disclosure. Сокращение навигации 8 → 4 подтверждено сравнением исходного компонента со снимком перед задачей; baseline browser-run до изменений не выполнялся. Рост конверсии, сокращение времени выполнения пользовательской задачи или улучшение CWV не заявляются.

## Проверки

Raw logs и снимки исходных файлов находятся в `.cache/v4-07-*`. Подробная сводка запусков — в [verification.json](verification.json).

- Полный Node: **367 PASS**, без skipped. Первый запуск: 365 PASS/1 module FAIL — VM-loader существующего теста компонента не подставлял новый словарь, а ожидания всё ещё описывали восемь пунктов. Обновлены import mapping и проверка четырёх локализованных разделов; проверки критических причин сохранены.
- ESLint и production build с TypeScript: **PASS**. После сборки код приложения не менялся.
- Пробный новый сценарий: **1/1 PASS**. Основной browser-run: **52 PASS / 12 FAIL**, без skipped/flaky. Новая приёмка четырёх разделов — все 8 случаев PASS; жизненный цикл редактора — все 24 случая PASS.
- Причины 12 сбоев основного прогона: восемь проверок `scrollY=0` после программного hash-перехода при плавной прокрутке; две проверки старого вложенного UTC-disclosure вместо существующего `.card-price-origin`; два ожидания сообщений сохранения внутри `#calculator`, которые теперь находятся в `#trip-save`.
- Для измерения геометрии используется штатный `prefers-reduced-motion: reduce`. Новый spec проверяет навигацию и с обычной прокруткой. Проверка источника цены теперь подтверждает видимые сведения и ISO timestamp; обе проверки storage/clipboard fallback сохранены на новом месте сообщений.
- [Повтор затронутых сценариев](repeat.json): **18/18 PASS**, без skipped/flaky. Все 64 случая основного набора имеют PASS по последним результатам; [исходный прогон](browser.json) и [пробный сценарий](pilot.json) сохранены отдельно.
- Дополнительный [layout-run](layout.json): первый экран PL/desktop прошёл на восьми ширинах 320–1440 px. Сенсорный RU/320 сценарий остановился до страницы поездки на устаревшем ожидании `sort=price` после выбора уже установленного значения по умолчанию. Setup изменён: сначала Recommended, затем Price; проверяются выбранное значение и фактическая сортировка с учётом канонического URL. Поисковый код не менялся.
- [Первый повтор сенсорного сценария](layout-final.json) дошёл до сохранения, но чтение localStorage совпало с навигацией в редактор и потеряло execution context. Добавлено ожидание URL редактора и восстановленной суммы перед чтением хранилища. [Финальный повтор](layout-recovery.json): **1/1 PASS**, включая сохранение, отправку, короткий viewport 400 px, возврат в каталог с прежними фильтрами и Back/Forward.
- По последним результатам **66/66 уникальных browser cases PASS**, без skipped/flaky в финальных запусках. Все повторные ошибки и результаты сохранены отдельно; полный основной набор после исправлений тестового setup не повторялся. Код приложения во всех прогонах совпадает с production build.
- Финальный `tsc --noEmit` после восстановления `next-env.d.ts`, полный ESLint и дополнительный ESLint последнего изменённого spec: **PASS**. Тестовые серверы на 3100/8100 завершены; исходное состояние `next-env.d.ts` восстановлено.

Покрытие нового browser spec: четыре локали PL/EN/RU/UK, desktop/mobile, ширины 320/375/390/768/1440, четыре соседних раздела, старые якоря, синхронизация проживания и бюджета, сохранность seller URL, общие ссылки и недоступные предложения. Axe проверяет `main`, размеры пунктов навигации — минимум 44 px по высоте. Это локальная автоматическая проверка, не ручной screen reader review и не пользовательское исследование.

[Матрица навигации](navigation.json) содержит восемь сочетаний языка/проекта и замеры на пяти ширинах для каждого.

Существующие регрессионные проверки сохранены и адаптированы к четырём основным пунктам: прямые старые hash-переходы проверяются отдельно. Проверки критических предупреждений, стоимости и сохранённого состояния не удалялись. Скриншоты `trip-navigation.spec.ts` теперь пишутся в output directory теста, чтобы повторный запуск не перезаписывал исторические отчёты.
