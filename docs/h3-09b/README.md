## Существующее основание и границы

До этой части главная показывала quality-gated short trips, три статические тематические ссылки и самостоятельные editorial destination cards. Загрузчик 09a уже определял три подборки через существующий API, независимые READY/EMPTY/ERROR и origin snapshot guard. Он ещё не вызывался главной. До изменений на сохранённой production-копии 09a прошёл один desktop PL home-hierarchy case: [baseline JSON](baseline.json), [лог](baseline.txt).

HomePage теперь параллельно с прежним short-trip запросом вызывает loadHomeCollections. HomeOrigin владеет общей секцией подборок: при несовпадении optimistic origin и серверного snapshot скрывает прежний комплект, показывает loading и aria-busy. Проверяются быстрый выбор второго аэропорта, пустой GDN, Back, reload и сброс на все аэропорты. Прежняя логика cookie/URL/history используется без второго механизма выбора.

Три подборки: календарная пятница–воскресенье, перелёт туда и обратно до 300 PLN за человека с 2–4 ночами по датам вылетов и ближайшие короткие поездки в порядке даты вылета. Календарный weekend не обещает прилёт домой в воскресенье или отсутствие отпуска. Даты/ночи и budget scope раскрыты в PL/EN/RU/UK. Сохраняются реальные query filters, origin, round_trip и locale; нет нового inventory или искусственных маршрутов.

Каждый preview показывает максимум три eligible предложения из просмотренных максимум 100 кандидатов. Это не полный подсчёт каталога. Пустой preview не объявляет глобальное отсутствие рейсов; ошибка и WEEKEND_QUERY_TOO_BROAD имеют отдельные тексты и retry. Ошибка одной подборки не скрывает остальные. С истечением первого срока offerDeadline весь соответствующий preview заменяется сообщением об устаревании и ссылкой на поиск/обновление: устаревшие цены не остаются активными рекомендациями. Используется существующий useOfferExpired, включая focus/visibility invalidation. До hydration сохраняется обычное ограничение этого существующего hook; серверные карточки уже проходят expiry gate загрузчика.

## Карточки, фотографии и совместимость

Предложения используют общий серверный DealCard, включая actual timeline, flight-only price, baggage caveat, airport warnings, freshness, details и score disclosure. Серверные children передаются клиентским state wrappers; новый клиентский дубль каталога не вводится. Повторяющийся offer может соответствовать нескольким intent collections. Impression по-прежнему использует существующий consent gate и dedup по событию/slug/route/session; analytics taxonomy не менялась.

Из существующего DestinationCard выделены DestinationPhoto и DestinationPhotoCredit. Тот же allowlist из трёх локальных WebP, alt всех языков, source/author/license, native keyboard details и missing/error fallback переиспользуются подборками и прежним editorial блоком. Новых изображений, лицензий, remote image hosts или зависимостей нет. Изображение направления явно названо иллюстрацией. Фото не создаёт предложение без eligible offer; неудача картинки сохраняет карточку и action. Width/height 960×600, aspect ratio, responsive sizes/srcset и lazy loading сохранены, preload не добавлен. Браузерная проверка отдельно задерживает image responses и сравнивает рамку до/после загрузки. Это геометрическая проверка, не измерение production CWV.

Изначальные crawlable destination/airport/landing links, canonical/hreflang и indexed routes сохранены. H3-10 directory здесь не начинается. API runtime/schema/БД, saved/share, расчёт бюджета, affiliate attribution и consent не менялись. Дополнения Python относятся только к guarded e2e_app: синтетические one-offer, independent weekend errors/cap, short expiry и задержка GDN; production entrypoint их не импортирует.
