# HT-11 — сохранение и передача поездки

В калькуляторе предложения добавлены «Zapisz wyjazd» и «Udostępnij».
Сохраняется снимок маршрута, исходной цены/дат предложения и текущего бюджета,
включая даты плана, людей, оба режима жилья и неизвестные расходы.
Список `/saved` доступен из подвала и калькулятора. До 20 снимков хранятся
в localStorage (`hoptrip.saved-trips.v1`); одинаковый снимок не дублируется.
Удаление записи не удаляет другие поездки или черновики бюджета.

## Общая ссылка

Обновление 25 октября 2026 (пункт 7): необязательный `draft.events` в прежнем v1
содержит выбранные события и варианты билетов: ID, название, площадку, местные
дату/время, часовую зону, проверенную партнёрскую ссылку Ticketmaster, количество
билетов и собственную цену одного билета в PLN. Поля проходят allowlist, заметки
и прочие дополнительные свойства исключаются. Старые снимки без событий работают.
До 8 предложений, по 1–50 билетов. Прежний предел ссылки 6000 символов действует:
превышение поясняется явно и не обрезает события из локального черновика.
Получатель видит события и суммы, редактирует независимую копию. Список сохраняется,
даже если перелёт исчез или актуальный каталог событий недоступен.
События не бронируются и не обновляются автоматически; время/цена могут быть неизвестны.

Изначальный контракт ниже дополнен этими необязательными полями.

`/trip?plan=<base64url JSON v1>` содержит самостоятельный снимок, а не ссылку
на localStorage автора. Работает без аккаунта и БД планов. Получатель видит
снимок даже при отсутствии исходного предложения. Его черновик отделён
от черновика предложения и хранится под ключом копии. Изменения не меняют
ни ссылку, ни план автора. Новая кнопка «Udostępnij» создаёт новый снимок.

Передаются только разрешённые поля: маршрут/slug, исходные даты, сохранённая
цена и время наблюдения, числовые поля бюджета и его даты. Внутренний context,
контакты, произвольные дополнительные поля и заметки исключены сериализатором.
Валидируются также неактивные денежные поля жилья. Пустые расходы и нули
сохраняются раздельно; билет в одну сторону допускает неизвестный конец плана.
Неверные диапазоны, суммы, структура, версия и token > 6000 символов отклоняются.

Это редактируемый пользователем снимок, не подписанное предложение HopTrip.
Страница явно обозначает происхождение данных и отсутствие подтверждения цены.
Для прошедшей даты, исчезнувшего предложения и ошибки каталога есть отдельные
состояния. Текущая цена каталога не подменяет сохранённую цену плана.

## Превью и приватность

Серверные Open Graph/Twitter title и description показывают города и даты
плана с пометкой сохранённой копии; цену не рекламируют как актуальную.
Личные страницы не входят в sitemap, имеют noindex; общий план задаёт
no-referrer. Drive не загружается на `/trip` и `/saved`.

Данные доступны всем обладателям ссылки; пользователь видит пояснение перед
передачей. Ссылка не зашифрована, не отзывается и может попасть в историю и
логи запросов сервера. Политика приватности описывает это поведение.
При недоступном Clipboard API предлагается ручное копирование из поля.
При недоступном localStorage сохранение сообщает ошибку, но общая ссылка работает.

Ограничения: список локален для браузера; ссылки длинные; нет централизованного
отзыва, синхронизации и подтверждения личности автора. Сторонние мессенджеры
могут кэшировать или иначе отображать превью; проверяются сами метаданные.
Миграции и внешние сервисы для этой реализации не нужны.

## Воспроизведение

Проверки: 45 unit, 28 отдельных E2E desktop/mobile (shared-trip, trip-budget,
consent), включая повторный успешный прогон 12 сценариев после исправления
one-way. Axe, отсутствие overflow и мобильный скриншот проверены.
ESLint и production build с TypeScript проходят.

1. На странице предложения заполнить бюджет и даты, нажать «Zapisz wyjazd».
2. На `/saved` проверить запись после обновления.
3. Нажать «Udostępnij», открыть ссылку в другом профиле браузера.
4. Проверить маршрут, даты, людей и суммы. Изменить людей у получателя;
   после обновления копии изменение остаётся, у автора — прежние значения.
5. Удалить запись из списка: уже отправленная ссылка продолжает открываться.
6. Открыть повреждённую ссылку: понятное сообщение; для исчезнувшего предложения
   снимок и бюджет остаются доступными.
