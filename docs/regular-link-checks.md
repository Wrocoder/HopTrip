# Регулярная проверка ссылок достопримечательностей

Единый источник: `apps/web/src/lib/activity-expansion.json`, 68 городов / 71 карточка.
Шесть первоначальных карточек перенесены из TypeScript без изменения содержимого
или партнёрских URL. Фронтенд и проверка читают один JSON.

`hoptrip-links.timer`: ежедневно 07:00 Europe/Warsaw + случайная задержка до 10 минут.
Часовой пояс учитывает летнее/зимнее время. Persistent=true запускает пропущенную
проверку после включения таймера. Служба имеет лимит 30 минут и двух сетевых workers.
Повторный старт systemd не создаёт параллельную копию той же службы.

Проверяются только `href`, никогда `affiliateHref`. Перенаправления на tp.media,
tpx.gr и emrld.ltd и ссылки с tracking-параметрами не открываются. HTTPS проверяется;
приватные/локальные адреса отклоняются. Не скачиваются тела страниц, нет запросов
к API наличия билетов, покупок, имитации партнёрских кликов или обхода защиты сайтов.

Результат: `/var/lib/hoptrip/link-check/latest.json` и служебный `state.json`, mode 600.
Файлы заменяются атомарно; сохраняется последний отчёт и счётчики повторений.
В журнал systemd выводятся только количества и длительность, без полных ответов сайтов.

Статусы:

- OK: HTTP 2xx; изменение Tiqets slug допустимо при сохранении ID продукта.
- BROKEN: HTTP 404/410; подтверждение после двух проверок с интервалом минимум 20 часов.
- BLOCKED: 401/403/429; не означает, что ссылка недоступна посетителю.
- TEMPORARY: сеть/TLS/таймаут, 5xx и другие ответы, требующие повторной проверки.
- REVIEW: другой адрес/продукт, цикл или небезопасное перенаправление.

BLOCKED/TEMPORARY/REVIEW требуют трёх разнесённых по времени повторений, чтобы
получить confirmed=true. Это подтверждённая повторяемость проблемы проверки,
не доказательство удаления страницы. OK обнуляет счётчик; изменение href тоже.
Повторные ручные запуски в тот же день не повышают счётчик.
Карточки автоматически не скрываются и не переписываются.

HTTP 200 не гарантирует наличие билетов, правильность цен и отсутствие soft-404;
редакционная проверка содержания и условий покупки остаётся отдельной задачей.

Служба возвращает 0, если отчёт записан, даже при проблемах внешних ссылок.
Непрочитанный каталог/состояние или ошибка записи отчёта — ненулевой код.
Расписание и последний результат можно посмотреть без запуска новых проверок:

```sh
systemctl list-timers hoptrip-links.timer
systemctl show hoptrip-links.service -p Result -p ExecMainExitTimestamp
sudo cat /var/lib/hoptrip/link-check/latest.json
```

Ручная проверка: `sudo systemctl start hoptrip-links.service`.
Файл отчёта должен обновляться каждый день; если старше 36 часов, проверить службу.
Telegram включён владельцем 2026-10-04. Служба читает существующий
`/etc/hoptrip/monitor.env` и запускается с `--notify`. Новые подтверждённые проблемы
и восстановления отправляются в тот же чат/тему; одинаковые сообщения не повторяются.
Одиночные ошибки и штатные успешные проверки не создают сообщений.
Смена типа ошибки без OK не считается восстановлением. Удаление карточки из каталога
закрывает предупреждение и обозначается в сообщении вместе с восстановлениями.
Checkpoint `notifications.json` записывается только после успешной доставки;
при сбое доставки следующий запуск повторяет попытку. Ручной запуск безопасен для счётчиков.
Monitor каждые пять минут проверяет результат службы и свежесть отчёта (до 36 часов),
если timer включён; ошибки самой проверки тоже вызывают уведомления.

Установка: разместить script/catalog в `/opt/hoptrip`, units — в `/etc/systemd/system`,
затем `systemctl daemon-reload` и `systemctl enable --now hoptrip-links.timer`.
Отключение: `systemctl disable --now hoptrip-links.timer` (текущий oneshot при необходимости
останавливается отдельно). База данных и остальные службы не затрагиваются.
