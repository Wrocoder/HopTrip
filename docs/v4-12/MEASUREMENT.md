# V4-12 — сопоставимые измерения после отдельного rollout

В этом выполнении **нет новых production-измерений**. `synthetic-usage.json` и HTML dashboard содержат специально созданные пять сессий для QA; они не являются baseline продукта, доказательством конверсии или её улучшения.

Доступные read-only источники уже реализованы:

- `/api/v1/admin/analytics/usage?start=…&end=…` — агрегированный JSON.
- `/api/v1/admin/analytics/dashboard?start=…&end=…&locale=ru` — тот же период в HTML, без JS.
- Оба требуют существующий `X-Admin-Token`. Не помещать токен в URL, HTML, скриншот или сохранённый отчёт. Вывод не содержит session IDs и сырой metadata.

После отдельно разрешённого rollout сначала подтвердить версию API, затем web с тем же контрактом. Зафиксировать SHA, время UTC, границы периода, определения метрик и охват нового поля. Первое наблюдение без категории навсегда остаётся unknown **в данном окне**; нельзя дорисовать категории для старого baseline.

Для сравнения выбрать два неперекрывающихся периода одинаковой длительности, с теми же днями недели, сбором/consent-политикой и версиями событий. API допускает до 31 дня, default — семь дней. Для нового разреза оба периода должны иметь сопоставимый сбор категорий; сначала потребуется накопить baseline после появления поля. Изменившаяся доля unknown может означать изменение охвата, а не UX-эффект.

| Поле записи сравнения | Что сохранять |
|---|---|
| Релиз и окно | SHA, UTC start/end, продолжительность, локаль отчёта |
| Охват | observed_events/sessions, excluded_events, доля unknown и ошибки выдачи |
| Воронка | Для каждого этапа числитель, предыдущий знаменатель, процент; отдельно население каждой viewport-группы |
| Действия | Сессии с фильтрами/save/полным бюджетом/alert actions и все сессии группы |
| Контекст | Источники/локали/аэропорты и изменения трафика, кампаний, доступности предложений, календаря |
| Вывод | Разница наблюдений с объёмом выборки и ограничениями; без причинного вывода по одному сравнению |

Согласие, блокировки, сеть, неполное окно и best-effort transport ограничивают выборку. `0 / N` означает отсутствие полученного события среди N наблюдаемых сессий, а не доказанное отсутствие использования. `null` при нулевом знаменателе не заменяется нулём. Один session ID не равен одному человеку; возвраты между истёкшими сессиями не измеряются. Точные search/booking attribution и настоящая доставляемость уведомлений этим отчётом не устанавливаются.

Production query/export, новые внешние SaaS, уведомления и deployment в этой задаче не выполнялись. Эти измерения остаются внешним продолжением; локальная реализация и тесты отделены от измерения эффекта.
