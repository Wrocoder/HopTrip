# V4-12 — контракт измерений

Версия дополнения: `first-received-viewport-cohorts-v1`, 2026-11-08. Существующие 17 wire events и формат идентификаторов не меняются. В `metadata` добавлено необязательное поле `viewport`: `small`, `medium`, `large`.

| Группа | Ширина окна в CSS px |
|---|---|
| small | Больше 0, меньше 768 |
| medium | От 768 до 1024, не включая 1024 |
| large | От 1024 |
| unknown | На сервере: первый принятый event не содержит допустимого значения |

Клиент вычисляет только категорию из `window.innerWidth`, после проверки согласия на аналитику. Точная ширина, разрешение экрана, User-Agent, модель устройства и контакты не передаются. Новых cookies/ключей хранения нет. Изменение размера само по себе не создаёт событие, не меняет идентификатор сессии и не сбрасывает дедупликацию.

Сервер сохраняет только разрешённые три значения; отсутствующее или некорректное поле отбрасывается. Старый клиент совместим с новым API. Старый API отбросит новое поле, поэтому при отдельном rollout сначала нужен API; потерянные категории позднее не восстанавливаются. JSON metadata уже поддерживается существующей моделью, миграции не нужны.

## Когорты

`UsageReport.viewport_cohorts` — необязательное дополнение. Если поле отсутствует в старом отчёте, dashboard не рисует раздел. В новом отчёте `rows=[]` означает отсутствие наблюдаемых сессий, а не нулевую конверсию.

Внутри выбранного окна `[start,end)` учитываются те же продуктовые события и исключения, что и раньше. Для каждой сессии категория фиксируется по первому полученному событию: время сервера, затем ID записи. Это первое событие **в окне**, а не доказанное начало посещения. Поздняя категория, изменение размера или другая вкладка не переносят сессию; отсутствующее/некорректное первое значение остаётся `unknown`. Старые данные не дополняются через IP, заголовки, аналитику партнёров или более поздние события.

Каждая наблюдаемая сессия входит ровно в одну группу. Доля группы = её сессии / все наблюдаемые сессии. Это описание интерфейса, не определение физического устройства или человека. На одном телефоне может быть широкое окно, а на компьютере — узкое.

## Воронка и действия

В каждой группе применяется прежняя `ordered-session-funnel-v1`:

`PAGE_VIEW → SEARCH → положительный SEARCH_RESULT → DEAL_VIEW → PARTNER_CLICK того же предложения`.

Числа — уникальные сессии, прошедшие префикс в нужном порядке. Доля этапа считается от предыдущего этапа; при нулевом знаменателе — `null`. Сессии без PAGE_VIEW остаются в населении группы, но не попадают в воронку. Результат не привязывается к конкретному запросу: search ID по-прежнему отсутствует. Клик не является бронированием или комиссией.

Отдельная таблица показывает долю сессий группы с `FILTER_USE`, `TRIP_SAVE`, `BUDGET_CALCULATED`, `ALERT_STARTED`, `ALERT_CONFIRMED`. Повторы не увеличивают числитель. Знаменатель — **все наблюдаемые сессии группы**; действия до/без PAGE_VIEW тоже учитываются. Это не переходы между этими действиями: подтверждение email из новой сессии нельзя приписывать прежней заявке. Процент подтверждений от заявок не вычисляется. Завершение бюджета не подменяется первым редактированием поля (`BUDGET_USE`).

Существующие 11 основных метрик, engagement/origin/locale cohorts и общая воронка сохранены. `device_funnel` остаётся `unavailable`: аппаратный тип устройства не собирается. Новая категория ширины — отдельное измерение, а не восстановленная аппаратная информация.

## Соответствие пользовательских действий

| Действие | Существующее событие/данные |
|---|---|
| Отправить поиск | SEARCH |
| Получить выдачу/ошибку | SEARCH_RESULT с проверенными фильтрами и count/error |
| Применить/снять/сбросить фильтры | FILTER_USE с action |
| Увидеть/открыть предложение | DEAL_IMPRESSION / DEAL_VIEW |
| Открыть подробности | DEAL_DETAILS_OPEN |
| Перейти к партнёру | PARTNER_CLICK с ограниченной категорией/провайдером |
| Сохранить/изменить/удалить план | TRIP_SAVE / TRIP_UPDATE / TRIP_REMOVE после успешной записи |
| Изменить/завершить бюджет | BUDGET_USE / BUDGET_CALCULATED |
| Запросить/подтвердить email-alert | ALERT_STARTED / ALERT_CONFIRMED; не доставка и не Telegram opt-in |

До согласия, после отзыва/истечения и при некорректном consent optional tracking не выполняется; действия не переигрываются после разрешения. Сохранение использует keepalive перед полной навигацией: ответ может быть уже не виден браузерному Page, поэтому transport failure не превращается в автоматический повтор. Сервер сохраняет прежнюю дедупликацию по event_id. Публичный endpoint не доказывает подлинность согласия или человеческое происхождение произвольной отправки.
