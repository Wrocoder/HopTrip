# React #418: нулевое смещение часового пояса

Причина воспроизведена на публичных данных Лондона в локальном Next dev:
`flight-3672-2027-01-08`. В `TripAccommodation`, `#stay-schedule`, сервер Node
показывал `08.01.2027, 15:05 GMT+0 (Europe/London)`, Windows WebKit —
`08.01.2027, 15:05 GMT (Europe/London)`. Различие ICU в `timeZoneName: shortOffset`
заставляло React заново строить дерево. В production это был React #418.
[Ошибка до исправления](hydration-20261026/before.json).

Изменено: общий `flightTime` приводит обозначения нулевого GMT/UTC-смещения
к `GMT`. Местные часы, IANA-зона, ненулевое смещение и явное сообщение об
отсутствующей зоне сохраняются. Общая функция применяется в Nocleg и деталях
расписания во всех поездках.

Регрессия: добавлена изолированная зимняя фикстура WRO → STN, обратно LTN → WRO.
До изменения тест WebKit упал с тем же расхождением; после изменения сравнивает
текст исходного HTML с текстом браузера, проверяет отсутствие ошибок гидратации,
редактирование выезда, 4 ночи, «Do» и восстановление после перезагрузки.
Каталог фикстуры пустой и локальный, API провайдера не вызывается.

Проверено локально:

- WebKit: регрессия и полный сценарий поездки на 320 px прошли; отдельно прошли
  3 сценария проживания. Полный путь включает поиск, даты, событие, бюджет,
  сохранение, передачу и независимое редактирование копии.
- 76 unit-тестов: нулевое смещение в PL/EN/RU/UK, Лондон летом, Катманду с +5:45,
  существующие переходы DST, разные аэропорты и неизвестные зоны. ESLint и ruff прошли.
- Chromium: регрессия desktop/mobile, 8 сценариев расписания и полный мобильный
  путь 320 px успешны. Переход в первой проверке неизвестных данных выполняется
  клавишей Enter: проверяется навигация с клавиатуры, плавная прокрутка не смещает
  координаты автоматического клика. Desktop-вариант пути на 320 px намеренно пропускается.
- В тестовом переходе к партнёру сначала проверяются настоящий локальный 307 и
  host `partner.example`, затем браузер продолжает запрос на локальную заглушку.
  Это позволяет пройти тот же сценарий в WebKit, который не поддерживает
  `route.fulfill` для 307. Внешние партнёрские ссылки не открываются.

Воспроизведение из `apps/web`: задать SDK в `HOPTRIP_TEST_PYTHON`, для WebKit —
`HOPTRIP_TEST_BROWSER=webkit`, для Chromium — `HOPTRIP_TEST_BROWSER=chromium`,
`PLAYWRIGHT_CHANNEL=msedge`; выполнить `npm run test:e2e -- hydration.spec.ts --project=mobile`.

Далее: завершить сборку, CI, выпуск и контроль живого сайта.
Пункт 8 остаётся частичным: системный календарь, экранная клавиатура и полный путь
на физическом телефоне должны быть подтверждены владельцем по
[маршруту проверки](mobile-trip-device-check.md).
