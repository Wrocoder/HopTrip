# Редакция HopTrip · SOC-02

Локальная реализация от 24 октября 2026. Интерфейс: `/api/v1/editor/` на API-сервере.
По умолчанию выключен. Production в рамках этой задачи не изменён.

## Рабочий процесс

1. Войти отдельным паролем редакции.
2. Нажать «Новый черновик»: выбрать перелёт и событие либо гайд.
   Для перелёта в одну сторону указать последний день пребывания.
3. Проверить источник, наблюдение цены, даты, карточку и текст каждого выбранного канала.
4. Сохранить правки новой версией. Предыдущее одобрение перестаёт действовать.
5. Выбрать каналы и одобрить версию. Проверка источника выполняется повторно.
6. Скачать dry-run JSON: точные тексты, исходная SVG-карточка, источники, версия,
   контрольная сумма и срок одобрения. Перед выгрузкой источники проверяются снова.

Редакционное одобрение относится только к подготовке. В пакете `publishable=false`,
`accounts=[]`. Отправки, очереди доставки и подключения к аккаунтам здесь нет.
При подключении реальных аккаунтов потребуется новое одобрение с конкретными получателями.
Технические Telegram-уведомления и ежедневное обновление событий не затрагиваются.

Тексты публикаций — PL; редакционный интерфейс — RU. Доступны пять вариантов:
Telegram, Facebook, Instagram, TikTok, LinkedIn. Для Instagram/TikTok ссылка в подписи
не считается кликабельной. TikTok-вариант — текст для подготовки видео, не готовый ролик.
SVG хранится как исходник; конвертация в поддерживаемый платформой формат относится к адаптеру.

Первый гайд — «Bagaż: co naprawdę obejmuje cena biletu» (`/info/baggage`).
Его краткий редакционный текст и версия находятся в `services/editorial.py::GUIDES`;
при изменении исходной статьи обновлять этот manifest и увеличивать версию.
Это осознанный небольшой список, а не автоматический импорт всех статей.
Перелёты: до 50 свежих предложений по рейтингу; события: до 100 кандидатов за 31 день.
Для шаблона требуется цена перелёта для одного пассажира. Покупки перелёта и события раздельные.

## Актуальность и версии

Проверяется локальная БД: видимость и срок перелёта, срок наблюдения цены по общей политике каталога (6/24/48 часов в зависимости от близости вылета),
партнёрская ссылка, город и даты события, время относительно прилёта/обратного вылета,
статус продажи и возраст события (настроенный `EVENTS_MAX_AGE_HOURS`, сейчас 30 часов).
Это не онлайн-проверка наличия мест у продавца. Время на городской трансфер не гарантируется.

Снимок фиксирует цену, валюту, пассажиров, даты, расписание, событие и хеш условий источника.
Разница при одобрении/выгрузке блокирует действие. Срок версии — не более шести часов,
также ограничен ближайшим истечением источника. Срок не продлевается фоновым импортом.
«Обновить источник и тексты» создаёт новую версию и заново формирует тексты, чтобы старая
цена не сохранилась в подписи. Ручные правки следует проверить повторно.

`editorial_revisions` хранит неизменяемые снимки, тексты, точные итоговые варианты и SVG.
`editorial_approvals` фиксирует владельца, версию, каналы, хеш и срок.
`editorial_audit` фиксирует создание, редактирование, отклонение, одобрение и выгрузку.
Повтор одинакового одобрения идемпотентен. Одновременные правки одной версии:
одна сохраняется, другая получает 409 и требует повторного открытия черновика.

## Запуск с настоящей локальной БД

Применить миграции до единственной итоговой `0017_routes_editorial_merge` (включает редакцию и маршруты перелётов). Использовать настроенный Python проекта.
Из `apps/api`:

```powershell
python -m alembic upgrade head
python -m app.jobs.editor_password
```

Генератор дважды запрашивает пароль без отображения и выдаёт строку `EDITOR_PASSWORD_HASH`.
Сохранить её в локальном `.env` или серверном secret env, не в Git. Пример настроек:

```dotenv
EDITOR_ENABLED=true
EDITOR_OWNER=Dmitriy
EDITOR_PASSWORD_HASH=<результат генератора>
EDITOR_ORIGIN=http://localhost:8000
```

Для HTTPS — точный origin сайта без завершающего `/`, например `https://hoptrip.pl`.
Открывать редактор с этого же origin. Для Docker параметры уже передаются API-сервису;
после изменения env пересоздать API. Не включать редактор до применения миграции.

Сессии серверные, восемь часов; в БД только хеш bearer-токена. Cookie HttpOnly,
SameSite=Strict и Secure на HTTPS. CSRF-токен хранится только в памяти страницы;
проверяется также Origin. Технический ADMIN_TOKEN интерфейсу не передаётся.
Смена хеша пароля или EDITOR_OWNER завершает прежние сессии.
Вход ограничен пятью попытками в минуту на socket peer в одном API-процессе.
За reverse proxy лимит общий для его соединений; для нескольких API-процессов
понадобится общий лимитер. Текущая конфигурация API использует один worker.

## Проверки и изолированный предпросмотр

`test_editorial.py`: доступ, CSRF, Origin, пароль, лимит входа, версии, одобрение,
dry-run, смена цены/валюты/условий/события, истечение срока, смена шаблона, безопасный SVG.
`test_postgres.py`: миграция и конкурирующее редактирование в отдельных транзакциях.
`editor-ui.cjs`: полный сценарий desktop/mobile, axe, отсутствие ошибок JS и горизонтальной прокрутки.

Итоговая локальная проверка 24 октября: **467 тестов API прошли**, включая PostgreSQL;
`ruff` и `mypy` без ошибок. UI-сценарии desktop/mobile и axe прошли.

Для UI-проверки можно запустить исключительно тестовый сервер с временной SQLite:

```powershell
$env:HOPTRIP_EDITOR_E2E='1'
$env:PYTHONPATH=(Resolve-Path apps/api).Path
.venv/Scripts/python.exe -m uvicorn tests.editor_e2e_app:app --host 127.0.0.1 --port 8111 --no-access-log
```

URL: `http://127.0.0.1:8111/api/v1/editor/`, тестовый пароль `editor-browser-fixture`.
Этот сервер использует вымышленные данные и не должен запускаться в production.
В другом терминале: `node apps/api/tests/editor-ui.cjs` (использует установленный Edge
и зависимости Playwright/axe из `apps/web/node_modules`). Скриншоты и JSON-пакеты сохраняются
в `.worktrees/editor-preview/`. Для Linux можно указать `PLAYWRIGHT_CHANNEL=chromium`.

Следующий этап: отдельный Telegram-бот и тестовый канал, очередь доставки SOC-03,
конвертация карточки и повторное одобрение для конкретного получателя. Отправка тестового
или публичного поста требует отдельного разрешения владельца.

## Проверка после выделения ветки — 29 октября 2026

Редакция проверена поверх `0f74b27` в `feat/social-editor-20261029`.
Полный API-прогон с отдельной PostgreSQL: 628 passed, без пропусков.
Проверены создание БД с нуля и upgrade существующей `0016_flight_route_details`
до `0017_routes_editorial_merge` с сохранением записи каталога; конкурирующие
правки дают одну новую версию и один HTTP 409. Ruff и mypy прошли.

Исправлен срок редакционного снимка: теперь используется общий hidden_after
каталога, включая границы приближения вылета и более ранние сроки источников.
При остатке свежести цены 5 минут снимок и одобрение тоже истекают через 5 минут.
При неизвестном сроке создание снимка блокируется. Проверка источника при
одобрении/экспорте сохраняется.

Перед выпуском применить обычную процедуру deploy из operations.md с backup и
проверкой миграций/readiness. Редактор сначала остаётся `EDITOR_ENABLED=false`.
Для включения задать отдельный пароль через `editor_password`, `EDITOR_OWNER`
и точный `EDITOR_ORIGIN=https://hoptrip.pl`; на API поступает тот же Origin.
Настройки EDITOR_* наследуются API из базового compose; секреты в Git не вносить.
Затем проверить закрытый вход, сессию, создание/одобрение/выгрузку и выход на сервере.
Возврат `EDITOR_ENABLED=false` закрывает редакционные маршруты; это не требует
удаления таблиц и истории. Откат образа согласовать с инструкцией эксплуатации.

включён на production. Пароль хранится отдельно от репозитория. Серверные вход,
создание, одобрение, dry-run и выход проверены. Старые указания о локальном статусе
