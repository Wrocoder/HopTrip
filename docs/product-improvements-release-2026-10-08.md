# Продолжение улучшений HopTrip — 8 октября 2026

Опубликовано на hoptrip.pl 8 октября 2026 около 19:50 UTC; внешняя приёмка
продолжена 9 октября. Рассылка и события выключены, каталог жилья пуст.
Предыдущая работа по событиям, путеводителям и жилью сохранена.
Название партнёра на кнопке не добавлялось, как и просил пользователь.

## Что реализовано

- Aviasales: `currency=pln` добавляется в исходную ссылку до получения tracking URL.
  Маршрут, даты, параметры билета и `expected_price_currency` сохраняются.
  Старые ссылки заменит следующий штатный запуск синхронизации.
- Для `/deals`, `/from/WRO`, `/destinations/milan` подготовлены отдельные постоянные
  тексты, заголовки, описания, canonical и `index, follow`. Эти три страницы добавлены
  в sitemap: теперь 49 URL. Фильтры и пагинация `/deals?...` остаются `noindex, follow`;
  остальные аэропорты/направления не открываются массово без редакционной подготовки.
- Главная, каталог, аэропорт, направление и конкретная поездка получили OG/Twitter
  PNG 1200×630. В превью поездки указаны маршрут, дата и тип перелёта, без устаревающей
  цены. Иллюстрация нарисована кодом; сторонние изображения не скачиваются. Для
  отсутствующей/истёкшей поездки возвращается 404, при сбое API — 503 без кеширования.
- Подписка: приглашения на главной и в каталоге, перенос фильтров поиска,
  подтверждение email, изменение настроек и отписка. На страницах `/alerts` не
  запускаются аналитика и Drive; переход к форме выполняет полную загрузку страницы.
- Калькулятор: отдельная строка городского транспорта на человека за весь период поездки;
  подстановка по явному нажатию, свежему курсу NBP и выбранному числу билетов.
  Ручная сумма не перезаписывается, трансфер из аэропорта остаётся отдельным расходом.
  Пилот: ATM в Милане и T-casual в Барселоне. Для Парижа показан справочный диапазон
  отдельных приёмов пищи; он не выдаётся за полный дневной бюджет.

## Границы проверки партнёрского перехода

В чистом Chrome с локалью `pl-PL` проверялся прямой поиск
`https://www.aviasales.com/search/WRO1511MIL18111?currency=pln`:
панель валют показала Polish zloty. Проверка `locale=pl` на `.com` оставила язык

конечная цена продавца требуют проверки после публикации. Параметр валюты не
фиксирует цену билета и не конвертирует сохранённую цену предложения.

Документация, использованная при проверке:
[ссылки Aviasales](https://support.travelpayouts.com/hc/en-us/articles/5711895629714-Aviasales-affiliate-links),

## Рассылка: настройка и поведение

Миграция `0014_deal_alerts` добавляет две таблицы, не меняя существующие данные.
Сначала применить миграцию, затем обновить API, web и worker. Настройки есть в
`.env.example`, `.env.production.example` и Compose для обоих серверных процессов:

- `ALERTS_ENABLED=false` по умолчанию: форма не собирает адреса, приглашения скрыты.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY=ssl|starttls`, `SMTP_USER`,
  `SMTP_PASSWORD`, `SMTP_SENDER` — параметры выбранного почтового сервиса.
  Отправитель — обычный email без отображаемого имени. Только TLS с проверкой сертификата.
- `ALERTS_SIGNING_KEY` — случайный секрет не короче 32 символов, одинаковый в API
  и worker. При временном отключении рассылки сохранить ключ, чтобы работала отписка.
- `ALERTS_SITE_URL` — HTTPS origin сайта; production Compose берёт его из
  `HOPTRIP_DOMAIN`. HTTP разрешён только для локальной разработки.
- `ALERTS_DAILY_SIGNUP_LIMIT=200` — общий предел запросов писем регистрации за
  скользящие 24 часа; PostgreSQL сериализует эту проверку между процессами API.

До включения нужно настроить домен отправителя у выбранного провайдера, проверить
его требования к SMTP, доставляемость и указать фактического почтового поставщика
в информации о конфиденциальности. Реальные SMTP-реквизиты в репозиторий не записывались.

Один адрес — один настраиваемый alert. Письмо регистрации отправляется не чаще
раза в 24 часа на адрес, включая повтор после ошибки SMTP. Ссылка подтверждения
действует 48 часов. Повторный анонимный запрос не меняет подтверждённые настройки:
после интервала адресат получает ссылку управления. Отписка требует явного POST;
автоматический GET из почтового сканера ничего не подтверждает и не выключает.

Токены подписаны HMAC, не содержат email и передаются в fragment ссылки, затем
в теле запроса. API не возвращает email при управлении; адрес, токен и ответы SMTP
не попадают в журналы приложения. Защита почтовой ссылки зависит и от того, кому
пользователь её пересылает.

После каждого цикла scheduler вызывается задача уведомлений, даже при сбое
поставщика рейсов. Можно отдельно запустить `python -m app.jobs.alerts` в окружении
API. Задача использует те же ограничения свежести, цены, аэропорта, дат и ночей,
что каталог, берёт до 10 предложений и отправляет не чаще раза за 24 часа.
Пустые подборки не отправляются. Повтор предложений исключается в пределах
90-дневного журнала отправок.

Резервирование набора и времени отправки записывается до обращения к SMTP.
Строка подписки блокируется при отправке: конкурентный worker не отправляет второй
набор, а завершившаяся отписка исключает следующие отправки. При разрыве соединения
или падении процесса зарезервированный набор автоматически не повторяется:
это сознательный выбор в пользу отсутствия дублей, возможен пропуск письма.
Для рабочей рассылки использовать PostgreSQL; SQLite служит локальным тестовым стендом.

Удаление данных выполняется той же задачей и при `ALERTS_ENABLED=false`:
неподтверждённые записи — через 7 дней, отключённые — через 30 дней, журнал — через
90 дней. Worker необходимо оставлять работающим для соблюдения этих сроков.

стоимость жилья/питания. Эти цены из него не выводились.
