# HT-13 — персональные подборки

Статус: DONE, 2026-10-12. Реализация и тестовый транспорт проверены локально.
Production-расписание и реальные рассылки не включались; миграций нет.

## Отбор и письмо

`app.services.alert_digests` выбирает до пяти новых предложений по цене,
затем по ID для стабильного порядка. Применяются аэропорт, максимальная цена
перелёта на человека, минимальные/максимальные ночи, направление, обе границы
дат вылета и выходные из сохранённых настроек HT-12. Используется общая проверка
доступности каталога: видимость, ACTIVE, свежесть до 48 часов, срок действия,
будущий вылет. Неактивные направления исключены. Требуется известный обратный
перелёт: продолжительность one-way не подменяется нулём или вымышленным возвратом.
Выходные — пятница/суббота до ближайшего воскресенья, один-два дня.

Если подходящих новых вариантов нет, письмо и запись отправки не создаются.
Слот не расходуется: появившееся позже в тот же день предложение может попасть
в подборку. Неподходящие варианты для заполнения письма не добавляются.

Польский текст содержит маршрут с аэропортом, даты, ночи, наблюдаемую цену,
время обновления данных в Варшаве, известное число пересадок либо «brak danych»,
оговорки о багаже/тарифе, отдельной оплате жилья и трансферов, изменении цены
и доступности. Дата обновления не называется проверкой цены у продавца.
Есть ссылка на `/deals/<slug>` и действующая ссылка управления/отписки HT-12.
Письмо не обещает поездку без отпуска или гарантированную цену.

## Расписание и повторные попытки

Отдельный `app.jobs.alert_scheduler` проверяет очередь раз в 60 секунд.
Он независим от загрузки предложений и подключается только профилем Compose
`alerts`. По умолчанию `ALERTS_DIGEST_ENABLED=false`.

| Настройка | По умолчанию | Значение |
| --- | --- | --- |
| ALERTS_ENABLED | false | Разрешение подписок и проверка SMTP-конфигурации |
| ALERTS_DIGEST_ENABLED | false | Отдельное разрешение рассылки |
| ALERTS_DIGEST_WEEKDAY | 0 | День недельной подборки: понедельник=0, воскресенье=6 |
| ALERTS_DIGEST_HOUR | 9 | Час начала в Europe/Warsaw, 0–23 |
| ALERTS_DIGEST_MINUTE | 0 | Минута начала, 0–59 |

Weekly получает не более одной попытки за семь календарных дней, только
в выбранный день недели; daily — не более одной попытки за календарный день.
Daily — обычная подборка, не срочное уведомление о падении цены.
Начало окна — заданное местное время, конец — местная полночь. После перезапуска
внутри окна возможна одна догоняющая подборка; прошедшие дни не воспроизводятся.
Смена настроек не обнуляет предыдущую попытку отправки.

Переход на летнее/зимнее время учитывается через Europe/Warsaw. Календарный день
может длиться 23/25 часов. Повторный местный час не создаёт второе письмо;
несуществующее время весной обслуживается при первой проверке после скачка часов.

Для каждой подписки перед SMTP сохраняются список ID предложений, время
попытки и статус RESERVED. PostgreSQL row lock сериализует конкурирующих
обработчиков. После фиксации повторно проверяются статус и фильтры: отписка
или изменение настроек до отправки дают CANCELLED. Во время самого SMTP-вызова
блокировка подписки сохраняется: уже начатую передачу письма отозвать нельзя,
но после успешного ответа API отписки новые отправки не начинаются.

Успешный вызов SMTP даёт SENT; исключение — UNCERTAIN; аварийное завершение
может оставить RESERVED. Все эти попытки, включая CANCELLED, расходуют слот
и исключают зарезервированные ID из следующих подборок. Автоматического
повтора нет даже через неделю: SMTP не позволяет надёжно отличить принятое
письмо от непринятого при обрыве соединения. Это гарантия отсутствия повторной
попытки, а не гарантия доставки каждого письма. ID существующего предложения
сохраняется при обновлении его цены; новая цена не порождает повторную рассылку.

История активной подписки сохраняется весь срок её действия для защиты от дублей.
При включённом обработчике удаляются неподтверждённые записи старше 7 дней
и отписанные старше 30 дней вместе с их историей. В логах только счётчики
и безопасные сообщения, без email, SMTP-ответов, токенов и секретов.

## Проверки и запуск

Локально: 361 API-тест прошёл, 6 PostgreSQL-тестов пропущены без тестового
сервера/TEST_DATABASE_URL. В том числе 40 новых проверок формирования письма,
всех фильтров, пустого результата, дедупликации, частоты, DST, отписки,
изменения настроек перед отправкой, неопределённого SMTP-результата,
аварии после резервирования, очистки и выключенного планировщика.
Добавлен PostgreSQL-тест двух конкурентных обработчиков; он входит в пропуски,
поэтому конкурентное исполнение в PostgreSQL в этом запуске не подтверждено.

Воспроизводимый локальный запуск тестов: проектный Python из PyCharm,
`-m pytest apps/api/tests/test_alert_digests.py apps/api/tests/test_alert_preferences.py -q`.
Для проверки конкуренции на выделенной тестовой БД `hoptrip_test` задать
TEST_DATABASE_URL и выполнить `-m pytest apps/api/tests/test_postgres.py -q`.
Тесты используют подменённый транспорт и адреса example.test, реальных писем нет.

Ruff, mypy (71 файл), Compose config и git diff --check проходят.
Docker daemon на рабочей машине недоступен; контейнерный запуск не выполнялся.

Будущий production-запуск требует отдельной команды владельца: после публикации
кода, проверки PostgreSQL-конкуренции и готовности публичных ссылок включить оба
флага, настроить время и запустить `alerts-worker` профилем `alerts` с production
Compose override. Текущие тексты сайта о том, что подборки ещё не запущены,
нужно обновить при этом запуске. Секреты используются из серверного env;
в репозиторий и командную строку их не копируют. Эта инструкция не выполнялась.
