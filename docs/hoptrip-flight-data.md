# HT-06: данные карточки перелёта

Проверено 2026-10-11. Реализация локальная; production не обновлялся.

## Контракт

API выдаёт flight_facts в списке и деталях. Сырой payload и партнёрские
параметры не публикуются. Интерпретируется только FLIGHT из travelpayouts_data;
для других источников поля остаются неизвестными. Из справочника Airport
сохраняется известный аэропорт вылета. Миграция не нужна.

Поля сверены с разделом prices_for_dates в
[официальной документации Aviasales Data API](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).
Источник описывает аэропорты отдельно от кодов направления, авиакомпанию кодом IATA,
пересадки и длительность отдельно для каждого плеча. Это сохранённые предложения,
не подтверждение текущего наличия.

| Источник | Публичное поле / представление |
| --- | --- |
| origin_airport, destination_airport | Только валидный трёхбуквенный код аэропорта |
| destination | Код направления; без destination_airport не подтверждает аэропорт |
| airline | Двухсимвольный код IATA перевозчика, без догадок о названии или перевозчике возврата |
| transfers / return_transfers | Число пересадок отдельно; 0 означает без пересадок, null — неизвестно |
| departure_at / return_at | Только ISO timestamp с явным смещением; departure_precision=DATE запрещает часы вылета |
| duration_to / duration_back | Положительные целые минуты; расчёт прилёта из соответствующего отправления |
| Багаж | Достоверного поля нет; всегда «Bagaż do sprawdzenia u partnera» |

Для отсутствующих/невалидных данных выводится «do sprawdzenia u partnera».
Булевы, отрицательные, дробные и строковые числа не становятся подтверждёнными
пересадками/длительностью. Не выводятся часы из искусственной полуночи date-only,
URL билета не декодируется в расписание.

## Время и ограничения

Все показанные часы явно обозначены UTC, не временем аэропорта или браузера.
Смещения ISO источника учитываются при преобразовании в UTC.
Прилёты обозначены как рассчитанные по длительности источника.
Интервал — обратное отправление минус прибытие, по абсолютным моментам:
корректен при разных смещениях и смене летнего времени. Отрицательный или
неполный интервал не показывается. Это период между рейсами, включающий
ночлеги, трансферы и аэропортовые процедуры, а не доступное время прогулок.

У текущего справочника нет надёжного покрытия IANA-зонами аэропортов.
Для отображения всех прилётов в местном времени нужен отдельный справочник
с зонами и проверкой DST. Новая интеграция в HT-06 не добавлена.
Нет подтверждённого состава багажа, списка сегментов и перевозчиков каждого
плеча, отдельных аэропортов возврата. Код перевозчика источника не означает,
что он выполняет все сегменты. Часы и длительности могут отсутствовать.
Процент покрытия production не измерялся; тестовые примеры не являются
статистикой реальных предложений.

Даты/дни недели и календарные ночи сохранены. Цена подписана «za osobę ·
w obie strony» либо «za osobę · w jedną stronę» в карточке, деталях и у кнопки.
Карточка и детали используют один компонент FlightFacts.

## Воспроизведение

Запустить локальные Playwright fixtures с PLAYWRIGHT_CHANNEL=msedge и
HOPTRIP_TEST_PYTHON, указывающим на SDK проекта:
npm --prefix apps/web run test:e2e -- flight-facts.spec.ts polish-locale.spec.ts catalog.spec.ts

В /deals первая карточка browser-deal имеет неизвестное расписание и багаж.
browser-13 — отдельный локальный тест с возвратом, известными аэропортами,
кодом FR, 0/1 пересадками и интервалом 70 часов. Проверить те же сведения
после перехода в детали и отсутствие горизонтального скролла на мобильном.
Реальные билеты и внешние партнёрские переходы для этой задачи не требуются.
