### Политика URL и данных

- Индексируются постоянные страницы из реестра catalogPages и опубликованные
  руководства; собственный canonical. WAW/WMI сохраняют отдельные URL и прежний
  noindex до самостоятельной редакционной подготовки. Нет массовых страниц маршрутов.
- Произвольные поддерживаемые фильтры и страницы выдачи — noindex, follow, собственный
  нормализованный canonical. Порядок параметров стабилен; UTM и неизвестные параметры
  не меняют выдачу и не входят в canonical. Значения сценария убираются из URL как
  эквивалентные умолчания; offset=0 и sort=score без пагинации нормализуются.
- Другие сортировки сохранены: при постраничном выводе они меняют состав конкретной
  страницы, поэтому canonical на страницу с другой выборкой был бы некорректен.
- robots.txt позволяет прочитать noindex; /api/ и /go/ остаются закрыты обходу.
  Sitemap не содержит фильтров. Для новых подборок lastmod не выдуман; дата сборки
  не используется как дата обновления. У руководств используется редакционная дата.
- Пустая постоянная подборка остаётся 200 с описанием условий, ссылками и явным
  действием расширения поиска. Ошибка API отделена от отсутствия предложений.
- Календарные даты генерации Deal теперь переводятся в IANA-зоны аэропортов по
  исходным timestamp. При отсутствии зоны сохраняется исходная дата с offset;
  date-only не превращается в расписание. URL существующих предложений не меняются.
  Уже сохранённые Deal получат исправленные даты при штатной повторной генерации
  после выкладки; production job в этой сессии не запускался.
- Подписка поддерживает один аэропорт. Для WAW+WMI ссылка честно предлагает выбрать
  аэропорт подписки, сохраняя другие поддерживаемые условия; объединение нельзя
  передать как несуществующий IATA. Рассылка не включалась.

### Измерение после отдельной выкладки

Собственный API `/api/v1/admin/analytics/summary` (требует действующего admin-доступа)
показывает `by_event`, сессии, переходы и подтверждённые конверсии. Схема:

| Событие | Когда учитывается |
| --- | --- |
| SEARCH / FILTER_USE | Валидная отправка формы / действие фильтра; это разные показатели, их нельзя складывать как число поисков |
| SEARCH_RESULT | Получена выдача или ошибка; повторный render не добавляет просмотр |
| DEAL_VIEW | Открыта страница предложения |
| BUDGET_USE | Первое непустое валидное изменение поля расчёта при данном посещении; не загрузка начальных значений и не каждое нажатие |
| TRIP_SAVE | Новый снимок плана действительно записан в localStorage; повтор той же версии и ошибка storage не считаются успехом |
| ALERT_CONFIRMED | API подтверждения email ответил успешно; запрос письма не является подпиской |
| PARTNER_CLICK | Действие партнёрской ссылки, с существующей категорией/provider; не покупка |

Разрешён `metadata.page_type`: home/catalog/city_break/weekend/origin/destination/
route/deal/budget/saved_trip/alerts/guide. Фильтры проходят allowlist; WAW,WMI —
единственная разрешённая группа кодов. Capability URL подписок не передаётся;
для их страниц разрешено только успешное ALERT_CONFIRMED. Согласие аналитики
не равно согласию на письма. Без аналитического consent событие не отправляется.

Для воронки за одинаковый период считать **уникальные anonymous_session_id**:
сессии с поиском → с просмотром оферты → с бюджетом → с сохранением.
Конверсия этапа = сессии с обоими последовательными событиями / сессии входного
этапа; порядок проверять по created_at. Для такой последовательности нужна
авторизованная выгрузка analytics_events (без иных таблиц и персональных полей),
так как агрегат by_event сам по себе не доказывает переход одной сессии.
Сессия не равна человеку; блокировка storage/consent и разные устройства ограничивают
полноту. Подписки и партнёрские клики считать отдельно. Доход — только подтверждённые
комиссии партнёра, которых в этой сессии не получали.

Search Console доступа нет. Необходимы следующие выгрузки и действия владельца:
