# Запись приёмки выпуска

Это незаполненный шаблон, не подтверждение развёртывания. Для каждого выпуска
создайте отдельную запись с датой и SHA. Не прикладывайте секреты, приватные ссылки
бронирования и необработанные provider responses. Храните чувствительные доказательства
отдельно; здесь достаточно результата и безопасной ссылки на запись.

## Версия

- Дата / проверяющий: не заполнено
- Commit SHA / CI run / итог: не заполнено
- Режим: bootstrap без данных / реальные flight-only предложения — не выбран
- Hostname / архитектура VM: не заполнено
- Предыдущая рабочая версия и backup перед миграцией: не заполнено

## До развёртывания

- [ ] CI успешно проверил выбранный SHA: backend, migrations, frontend, browser.
- [ ] Проверены production hostname и сборка под архитектуру VM.
- [ ] Финальные контакты/privacy/terms содержат настоящие данные оператора.
- [ ] Сохранён backup старой БД, если она существует; read-only preflight не нашёл конфликтов.
- [ ] Порядок остановки writers, миграции и запуска согласован с operations.md.

## Сайт и эксплуатация

- [ ] Снаружи доступны HTTPS, главная, `/info` и `/health/ready`; нет redirect на неверный host.
- [ ] Canonical и sitemap содержат production URL; черновики не индексируются.
- [ ] Порты БД/API/web не доступны напрямую из интернета.
- [ ] Выбранное расписание maintenance выполняется независимо от ingestion.
- [ ] Мониторинг получил успешный результат и уведомление о тестовом отказе.
- [ ] Контролируется отсутствие запусков мониторинга; есть проверка снаружи VM.
- [ ] Backup создан, скопирован вне VM; выбран retention и проверен доступ к копии.
- [ ] Restore выполнен в отдельную пустую БД; проверены revision и контрольные записи.

Результаты / дата / безопасные ссылки: не заполнено.

## Реальные предложения и партнёрские переходы

Для bootstrap этот раздел остаётся незавершённым: worker и монетизация не объявляются готовыми.

- [ ] Подтверждены права на cached данные и хранение истории, market/PLN/лимиты.
- [ ] Настоящий ответ проверен; указаны число записей и причины пропусков без raw payload.
- [ ] Программа действительно одобрена; сохранены правила, host, SubID и дата проверки.
- [ ] Компонент связан с программой и настоящей ссылкой через admin API.
- [ ] Реальная сделка соответствует маршруту/датам/цене; CTA ведёт к ожидаемому партнёру.
- [ ] Клик сохранён, SubID подтверждён доступным отчётом партнёра.
- [ ] Worker обновляет данные в пределах лимитов, повтор не увеличивает историю ошибочно.
- [ ] Понятен способ сверки статуса бронирования и комиссии; реальная сверка отмечается
  отдельно после появления отчёта, покупка билета только ради проверки не требуется.

Результаты / ограничения / следующий шаг: не заполнено.

## Решение

- Статус: **не проверено**.
- Незакрытые пункты / ответственный / срок следующей проверки: не заполнено.
- Возврат к предыдущей версии: проверить совместимость схемы; не выполнять слепой
  downgrade. Восстановление — в отдельную БД по operations.md, с проверкой до переключения.
