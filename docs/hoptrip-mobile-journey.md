# HT-16 — мобильный сценарий

Статус: DONE. Проверка 2026-10-12 на локальных фикстурах. Рабочие ширины: 360, 390, 768 px;
сравнение с десктопом 1440 px. Использован Edge/Chromium через Playwright.
Публичный сайт и реальные бронирования в этом запуске не изменялись.

## Исправление

Воспроизведено: неверный диапазон дат переводил фокус на последнее поле,
но у поля отсутствовали aria-invalid и ссылка на пояснение. Ошибка была
видна текстом, однако не входила в доступное описание сфокусированного поля.

В FilterForm добавлены уникальный ID ошибки и признак ошибочного поля.
Даты, длительность, AirportSelect и DestinationSelect получают aria-invalid
и aria-describedby. У подсказок аэропорта/направления сохранено прежнее описание.
После редактирования ошибка и её связь с полем сбрасываются.

## Сценарий и доказательства

В tests/mobile-journey.spec.ts один сквозной сценарий повторяется на четырёх
ширинах: главная → отказ от необязательных cookies клавишей Enter → выбор
Wrocław стрелкой/Enter → длинный неверный ввод направления и понятная ошибка →
Barcelona из подсказки → раскрытие дат Space и переход Tab → неверный диапазон,
фокус и описание ошибки → исправление → поиск до 220 zł → сортировка по цене →
предложение → даты пребывания для one-way → ошибочная и корректная цена ночлега →
сохранение и восстановление бюджета → партнёрская ссылка клавишей Enter.

Партнёрский переход проходит настоящий локальный API: проверяется ответ 307
и адрес fixture-партнёра, затем браузер перенаправляется на локальную страницу.
Это не проверка Stay22 и не закрытие HT-05.

Проверены отсутствие горизонтальной прокрутки, доступность центра кнопки
приватности, поля бюджета и партнёрской ссылки (elementFromPoint), подписи
и axe для main на странице предложения. Закреплённая кнопка не добавлялась:
существующий переход доступен без перекрытия контента.

## Измерения и ограничения

Итог: [11 desktop E2E](ht16/desktop-report.json), включая четыре сквозных
сценария и регрессию аэропортов, направлений и дат; дополнительно
[4 mobile E2E](ht16/mobile-report.json) с touch/mobile-эмуляцией Chromium.
Все прошли. Также прошли 45 unit-тестов, ESLint и production build с TypeScript.
Первая проверка воспроизвела отсутствующий aria-invalid; после исправления
проверены описание ошибки и сброс при редактировании. Ошибка тестового сценария
с незаданной датой возврата для one-way исправлена заданием дат пребывания.

[Navigation Timing](ht16/navigation-metrics.json): один reload страницы предложения
для каждой ширины, локальный development-сервер, без ограничения CPU/сети.
TTFB 251–265 мс; DOMContentLoaded 676–732 мс. transferBytes относится только
к HTML-документу, не ко всем ресурсам. Эти диагностические значения не являются
Lighthouse-оценкой, Core Web Vitals или полевыми данными и не характеризуют
скорость сайта у реального пользователя.

Для приближения открытой клавиатуры высота viewport уменьшается до 400 px:
поле остаётся доступным, decimal inputMode сохранён, горизонтального переполнения
нет. Настоящие клавиатуры iOS/Android, нативный календарь и системные safe areas
на физических устройствах не проверялись. Даты проверены через заполнение
нативных input type=date, их валидацию и переходы фокуса; браузерная эмуляция
не подтверждает поведение системного date picker или VoiceOver/TalkBack.

Воспроизведение: задать HOPTRIP_TEST_PYTHON путём к SDK проекта, затем из apps/web
`npx playwright test tests/mobile-journey.spec.ts`. В этой среде использован
PLAYWRIGHT_CHANNEL=msedge, поскольку комплектный Chromium Playwright не установлен.
