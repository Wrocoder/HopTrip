## Что сделать владельцу

1. Сначала опубликовать пакет. Проверить открытие четырёх URL без авторизации,
   HTTP 200 и наличие адресов в https://hoptrip.pl/sitemap.xml.
2. Открыть Google Search Console и подтверждённый ресурс hoptrip.pl
   (или URL-prefix https://hoptrip.pl/). Если ресурс ещё не подтверждён,
   выполнить предложенную Google проверку владения.
3. В «Файлы Sitemap» отправить https://hoptrip.pl/sitemap.xml, если он ещё не добавлен.
   Если уже добавлен — проверить успешное чтение и дату последнего чтения;
   не создавать дубли sitemap для отдельных статей.
4. В верхнем поле «Проверка URL» по очереди вставить каждый адрес выше.
   Нажать «Проверить опубликованный URL». При успешной проверке нажать
   «Запросить индексирование». Это запрос Google, а не гарантия попадания в поиск.
5. Через несколько дней повторно открыть проверку URL: статус индексирования,
   последний обход, заявленный и выбранный Google canonical. Live test показывает
   доступность сейчас, но не подтверждает наличие в индексе. Обход может занять
   от нескольких дней до нескольких недель. Повторная ежедневная отправка не ускоряет его.
6. Если «Исключено тегом noindex», блокировка robots или ошибка сервера относятся
   к этим четырём чистым URL — передать точную причину и результат live test для
   диагностики. Для URL фильтров noindex намеренный, снимать его массово не нужно.
7. В «Эффективность → Результаты поиска» выбрать страну Польша, тип поиска Web,
   отфильтровать новые страницы. Смотреть показы, клики, CTR и среднюю позицию;
   бренд HopTrip учитывать отдельно. Сохранить дату фактической публикации.

Ориентиры запросов: `Norwegia wieloryby`, `Tromsø wieloryby kiedy`, `Norwegia lodowce`,
`Islandia wieloryby`, `Islandia lodowce`, `Islandia co zobaczyć`.
Это редакционные гипотезы по теме, а не подтверждённые объёмы поиска.
Первые данные собирать после публикации; начальную оценку делать по полному периоду
наблюдения (например, 28 дням), не обещая позиции или рост за этот срок.
