## Поведение и контракт

- `budget-estimates.ts` хранит optional `budget-estimates-v1`, currency строгоPLN, selected profile и до3 набора диапазонов. Ночлег — группа/ночь либо группа/весь срок; еда — человек/день; доезды — группа/весь срок. Подсказка просит не повторять отдельно учтённый транспорт. Отдельного источника цен и FX для моделей нет.
- `projectBudget` переиспользует существующий exact calculator. Любая заполненная scalar сумма, включая0 и сумму из reference, имеет приоритет над моделью; выбор/редактирование/удаление профиля не меняют exact inputs, events или provenance. Полёт добавляется ровно один раз; известная часть событий сохраняется, неизвестная часть остаётся unknown. Остальные категории не моделируются. Полный trip ceiling не заявляется, пока хоть одна категория неизвестна: явно показаны partial range и список неизвестных расходов.
- Нижняя/верхняя суммы вычисляются в целых грошах. Per-person границы округляются наружу: floor(min/people), ceil(max/people). Ночи/дни меняются существующим date helper, same-day0night допустим. Неверные даты, числа, неполные или обратные границы не дают валидного projected range. Children модель не добавлена: сохранено существующее adult-only ограничение.
- Exact subtotal и scenario range показаны отдельно. В раскрытии сценария видны personal modeled assumptions и прежние OFFER/REFERENCE/MANUAL источники11a; это не live quote/бронь/гарантия. Активный профиль хранит собственный hotel basis независимо от exact формы, оба явно подписаны. Копирование exact суммы в модель разрешено только при совпадении hotel basis и двух пустых границах; частично заполненные диапазоны не затираются.
- Новые поля `BudgetDraft.estimates`/`estimatesRecovery` опциональны в прежнем version1. Local reader сохраняет временные опечатки для исправления, а при нечитаемой структуре модели оставляет exact бюджет/events/provenance и требует явного удаления повреждённых профилей. Strict share reader такие модели не принимает. Для save/share проверяются **все** настроенные профили, включая неактивные; arbitrary extras/notes/URLs отсекаются allowlist. UI предупреждает, что ссылка содержит все профили, включая невыбранные. Снимок не шифруется.
- Local restore, saved-card preview и received editable copy сохраняют диапазоны; правка полученной копии не меняет исходный snapshot. Старые local keys/version1, shared6000/local50000 и saved20 limits сохранены. [Совместимость](v1-compatibility.json): legacy token byte-identical, оба readers читают новые ссылки с теми же точными суммами, token identity/removal работают. Старый reader игнорирует модель и при повторном сохранении может её опустить; обещания её сохранения старой версией нет.
- Новых analytics events нет: прежний consent-gated BUDGET_USE; opt-out проверен. API/DB/schema/миграции/dependencies/SEO/affiliate поведение не менялись.
