# Что сделать владельцу HopTrip: пошаговая инструкция

Обновлено: 2026-09-21. Внешние инструкции проверялись 2026-09-20; фактическое
одобрение программы, доступность домена и стоимость видны только в вашем кабинете.
Ниже — ваши действия. Разработка без ожидания доступов вынесена в
[independent-development-tasks.md](independent-development-tasks.md).

## Быстрый маршрут

Интерфейс обновлён по [UI.md](UI.md): [открыть локальный сайт](http://localhost:58080).
Отчёт о редизайне и проверках — [ui-implementation.md](ui-implementation.md).

1. Выберите основной адрес сайта и зарегистрируйте домен — шаги 1–2.
2. Проверьте уже имеющуюся Oracle VM; создавайте новую только при необходимости — шаг 3.
3. Настройте DNS, подготовьте полезные страницы и публикацию по HTTPS — шаги 4–5.
4. Зарегистрируйтесь в Travelpayouts и получите токен данных — шаги 6–7.
   Регистрацию и получение доступного токена можно начать одновременно с доменом.
5. Подключите одну программу, получите образец ссылки и подтвердите правила — шаги 8–9.
6. Передайте разработчику несекретные сведения из шага 12 и пройдите приёмку — шаг 11.

Если программа проверяет сайт, сначала нужен содержательный сайт по шагу 5.
Локальные задачи I01–I18 выполнены. Дополнительно готовы три польские статьи о сравнении
цен, свежести и истории: [посмотреть локально](http://localhost:58080/info).
Вместе с about/partners это 5 из 25 страниц [SEO-плана](seo.md), остальные требуют подготовки.
Ожидая доступы, подготовьте сведения об операторе для контактов/privacy/terms и материалы
по аэропортам и направлениям из этого плана. Покупка домена, получение токена и
одобрение программы сами по себе ещё не означают готовность приложения к заработку.

## 1. Решить, что покупаем и какой адрес используем

| Что | Для чего | Что выбрать для первого запуска |
| --- | --- | --- |
| Домен | Адрес, который вводит посетитель | Один основной домен; для польского проекта сначала проверить варианты `.pl` |
| DNS | Направляет адрес на сервер | DNS регистратора достаточно для начала |
| VM | Запускает Next.js, API, worker и PostgreSQL | Сначала проверить существующую Oracle VM |
| HTTPS | Защищённое подключение | Предусмотренный проектом Caddy |
| Контактный email | Письма пользователей и партнёров | Реальный доступный ящик; адрес на своём домене можно добавить позже |

Составьте 2–3 варианта имени. Доступность `hoptrip.pl` и `hoptrip.com` не проверена;
это варианты для поиска, а не обещание, что их можно купить.
Для начала достаточно одного адреса, например корневого домена или `deals.<ваш-домен>`.
Если уже есть подходящий домен, отдельная покупка для поддомена не нужна.

**Результат:** записано точное имя, основной hostname и допустимая для вас цена первого
года/продления. Цены проверяйте в корзине с учётом VAT; промоцену не считайте ценой продления.

## 2. Где и как купить домен

### Основной вариант: OVHcloud Polska

Для этой инструкции беру OVHcloud как конкретный вариант покупки `.pl`, чтобы не выбирать
из десятков регистраторов. Это рабочий вариант, не утверждение о самой низкой цене.

1. Откройте [поиск доменов OVHcloud](https://www.ovhcloud.com/pl/domains/).
2. Введите выбранное имя целиком и посмотрите доступность.
3. Сравните стоимость регистрации и ежегодного продления. Если имя занято или продаётся
   как premium, сначала проверьте следующий вариант из списка.
4. Добавьте домен в корзину. Для существующего Docker-проекта на Oracle VM выбирайте
   регистрацию домена; дополнительный web hosting/конструктор не нужен для этой архитектуры.
5. Создайте свой аккаунт, укажите реальные контактные данные владельца и оплатите заказ.
6. Выполните подтверждения email, которые придут от регистратора, и проверьте статус домена
   в кабинете. Включите защиту аккаунта и сохраните доступ в менеджере паролей.
7. Проверьте дату окончания, порядок продления и платёжный метод; поставьте напоминание.

**Результат:** домен находится в вашем аккаунте; вы можете открыть его DNS-настройки.
Сохраните название регистратора, домен и дату продления.

### Альтернатива: Cloudflare Registrar

Для поддерживаемого расширения можно использовать [Cloudflare Registrar](https://domains.cloudflare.com/).
В кабинете откройте **Register domains**, найдите имя, выберите **Purchase**, срок,
контактные данные и оплату; подтвердите email. Проверьте регистрацию и автопродление.
Домены Cloudflare Registrar обязаны использовать DNS Cloudflare: если хотите другие
nameservers, выбирайте другой вариант регистрации.
[Официальная инструкция](https://developers.cloudflare.com/registrar/get-started/register-domain/).

Не покупайте один и тот же набор услуг у обоих регистраторов: выберите один путь.

## 3. Проверить сервер или создать его

### Если Oracle VM уже есть

В [operations.md](operations.md) описан вариант размещения за существующим HTTPS proxy.
Имя Docker network нужно подтвердить на вашем сервере; новую VM создавать только при необходимости.

1. Войдите в [Oracle Cloud Console](https://cloud.oracle.com/).
2. Откройте Compute → Instances и нужный экземпляр. Запишите public IPv4, ОС,
   архитектуру и регион.
3. Подключитесь своим SSH-ключом и выполните диагностические команды из
   [oracle-deployment-handoff.md](oracle-deployment-handoff.md).
4. Проверьте, кто уже занимает 80/443 и сколько свободно памяти/диска. При существующем
   Caddy используйте shared-proxy вариант; не останавливайте другое приложение ради HopTrip.
5. Заполните шаблон handoff: домен, public IP, SSH username, каталог развёртывания,
   существующая proxy network, место для резервных копий.

**Результат:** понятно, где размещаем сайт и какой вариант Compose применять.

### Если VM ещё нет

1. Создайте аккаунт через [Oracle Cloud](https://www.oracle.com/cloud/free/) и выберите
   регион с учётом нужных ресурсов.
2. В Console откройте Compute → Instances → создание экземпляра. Выберите Linux,
   поддерживаемый Docker, и ресурсы в пределах своего бюджета; проверьте оценку стоимости.
3. Настройте VCN/subnet с интернет-доступом, назначьте public IPv4, добавьте публичный SSH-ключ.
   Приватный ключ остаётся у вас.
4. Разрешите входящие 80/443 для сайта; SSH 22 ограничьте своим IP, где это возможно.
   Не открывайте наружу 5432, 8000 и 3000. Проверьте также firewall самой ОС.
5. Установите Docker Engine и Compose по [инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/),
   если выбрана Ubuntu. Для другой ОС используйте соответствующую официальную инструкцию.

[Пошаговое создание instance](https://docs.oracle.com/en-us/iaas/Content/Compute/Tasks/launchinginstance.htm).
Always Free зависит от home region, лимитов и наличия capacity; бесплатную VM нельзя
считать гарантированной. При нехватке capacity можно продолжать локальную разработку,
не переключаясь автоматически на платный тариф.
[Условия ресурсов Always Free](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

## 4. Привязать домен к VM через DNS

Нужны зарегистрированный домен и public IPv4 сервера из шага 3.

Для OVHcloud откройте **Web Cloud → Domain names → ваш домен → DNS zone**.
Если используются nameservers другого DNS-провайдера, менять записи нужно у него.
[Где редактировать зону](https://docs.ovhcloud.com/en/guides/web-cloud/domains/dns-zone-edit).

Добавьте A-запись через **Add an entry**, указав IP сервера в **Target**:

| Вариант | Тип | Имя записи | Значение |
| --- | --- | --- | --- |
| Сайт на корневом домене | A | Пустое поле в OVHcloud; в некоторых панелях `@` | Public IPv4 вашей VM |
| Сайт на `deals.<домен>` | A | `deals` | Public IPv4 вашей VM |

Выберите строку для своего основного адреса. TTL можно оставить стандартным. Если для
выбранного имени уже есть parking A/CNAME, замените только относящуюся к нему запись.
MX/TXT почты и записи других сайтов сохраняйте. AAAA добавляйте лишь при настроенном IPv6.
[Инструкция A-записи](https://docs.ovhcloud.com/en/guides/web-cloud/domains/dns-zone-a-record-creation).

Если выбран Cloudflare DNS, для первого прямого подключения к Caddy используйте запись
без HTTP-проксирования (DNS only). Это выбор схемы запуска HopTrip; CDN можно настроить позже.

Проверка из Windows PowerShell, заменив пример своим адресом:

```powershell
nslookup deals.example.com
nslookup -type=AAAA deals.example.com
Test-NetConnection deals.example.com -Port 443
```

**Готово:** DNS возвращает нужный IP. Проверка 443 станет успешной после запуска proxy
и открытия firewall; покупка домена сама по себе сайт не запускает.

## 5. Подготовить сайт для заявки партнёру

Подготовьте реальные тексты: что делает HopTrip, кому помогает, кто ведёт проект, как
связаться, как используются партнёрские ссылки. Для страниц аэропортов и направлений
соберите полезную информацию с источниками. Не заявляйте о существующем трафике или
ценах, которых нет. Фактические данные оператора нужны для публикации контактных
и privacy/terms страниц; разработчик может заранее подготовить структуру.

**Внутренняя подготовка выполнена:** сайт можно запустить без provider token и worker.
Страницы о сервисе и партнёрских ссылках подготовлены; контакты, privacy и terms остаются
черновиками до ваших реквизитов. Техническая приёмка описана в [статусе](implementation-status.md).
Не заполняйте конфигурацию фиктивными токенами/партнёрами ради запуска.

Разработчик разворачивает web/API/DB и страницы, а ingestion и CTA
включаются по мере готовности. При корректном DNS и доступных портах Caddy управляет
HTTPS автоматически; отдельная покупка сертификата для этой схемы не требуется.
[Как работает HTTPS Caddy](https://caddyserver.com/docs/automatic-https).

**Готово:** основной HTTPS-адрес открывается снаружи, есть полезные страницы и контакты.
Одной страницы «скоро откроемся» для нашей продуктовой цели недостаточно.

## 6. Создать аккаунт и Project в Travelpayouts

1. Откройте [Travelpayouts](https://www.travelpayouts.com/), зарегистрируйтесь и подтвердите email.
2. В onboarding укажите основной канал — сайт HopTrip — и его фактический адрес.
   Создайте Project с описанием польской аудитории и реальным текущим состоянием.
3. Если кабинет требует подтверждения владения сайтом, выполните предложенную процедуру.
   Для установки кода передайте разработчику инструкцию; не добавляйте автоматически
   неизвестный скрипт в проект.
4. Дополнительные каналы, например Telegram, указывайте отдельно, когда они появятся.

[Официальный стартовый процесс](https://support.travelpayouts.com/hc/en-us/articles/11394852618642-How-to-use-Travelpayouts-Quick-Start-Guide).
**Готово:** есть аккаунт и Project, описывающий настоящий источник трафика.

## 7. Получить доступ к данным о ценах

1. Войдите в [кабинет Travelpayouts](https://app.travelpayouts.com/).
2. Откройте **Profile → API token**, скопируйте существующий токен. Не нажимайте обновление
   без необходимости: оно сразу делает предыдущий токен недействительным.
   [Инструкция токена](https://support.travelpayouts.com/hc/en-us/articles/13024069738386-Where-to-find-API-token).
3. Сохраните токен в менеджере паролей и в `TRAVELPAYOUTS_API_TOKEN` нужного окружения:
   корневой `.env` для Docker Compose локально; `.env.production` — на сервере.
   Исходные шаблоны: [локальный](../.env.example), [production](../.env.production.example).
4. Разработчику сообщите «токен сохранён в таком-то окружении». Сам токен в чат/Git не нужен.
5. Адаптер I03 подготовлен; выполните один контролируемый запрос и проверьте статус, валюту,
   направление и дату источника. Пустой результат не означает отказ доступа.

По официальной инструкции cached Data API доступен с токеном после регистрации.
Это данные из кэша, а не гарантия текущей цены и не отдельный live Search API.
[Условия доступа](https://support.travelpayouts.com/hc/en-us/articles/203956083-Requirements-for-Aviasales-data-API-access).

**Текущий код:** адаптер переведён на `/aviasales/v3/prices_for_dates`, параметры и
нормализация проверены на HTTP fixtures. Это ещё не проверка вашего токена или реальных данных.
Доступность подходящих данных для польских маршрутов/PLN нужно подтвердить запросом.
[Документация данных](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API).

**Готово:** токен доступен приложению, известен результат запроса. Affiliate approval отмечается отдельно.

## 8. Выбрать одну доступную партнёрскую программу

С 27 апреля 2026 года Travelpayouts описывает автоматическое подключение Project к
подходящим программам: часть доступна сразу, часть требует проверки. Отдельная ручная
заявка на каждую программу больше не является стандартным первым шагом.

1. Откройте **My Programs**, выберите свой Project и вкладку **Available**. Найдите
   подходящую программу перелётов. Одна сеть не означает одинаковый доступ ко всем брендам.
2. Проверьте условия именно этой программы: Польша, website/SEO traffic, допустимость
   deep links, ограничения на продвижение, attribution, отчёты и выплаты.
3. Если нужного доступа нет, проверьте статус рассмотрения. Для дополнительных программ
   кабинет может предлагать **Unlock more programs**, после отказа — **Request review**.
   Сохраните название/ID, статус, дату обращения и ссылку на условия.
4. Если заявка ожидает рассмотрения, переходите к внутренним задачам. Не отмечайте
   APPROVED только потому, что аккаунт Travelpayouts уже создан.

Доступ зависит от программы и Project.
[Официальная инструкция программ](https://support.travelpayouts.com/hc/en-us/articles/360021216060-How-to-start-working-with-affiliate-programs).
**Готово:** одна программа явно доступна этому Project; её статус и правила сохранены.

## 9. Где получить партнёрскую ссылку

Для первого образца автоматический генератор в HopTrip ещё не нужен.

1. На сайте выбранного бренда откройте нужную страницу, например результаты поиска
   перелёта. Скопируйте адрес из адресной строки браузера.
2. В Travelpayouts откройте **Tools**, выберите Project и **Links**.
3. Вставьте исходный URL в **Destination page**. Укажите тестовый SubID, например
   `hoptrip_setup`, если поле доступно.
4. Нажмите **Generate link & QR code** и сохраните полученную партнёрскую ссылку
   вместе с исходным URL. Это разные ссылки.
5. Если генерация сообщает об ожидании/отказе, вернитесь к статусу программы.
   Сгенерированный адрес передайте разработчику без самостоятельной перестройки параметров.

[Официальный процесс создания ссылок](https://support.travelpayouts.com/hc/en-us/articles/360027634052-How-to-create-and-use-affiliate-links).

Сохраните partner ID/marker из кабинета и Project ID. Для partner-link API параметр `trs`
соответствует ID подписанного на программу Project; `marker` — ID партнёра.
[Контракт автоматического генератора](https://support.travelpayouts.com/hc/en-us/articles/25289759198226-API-for-Travelpayouts-partner-links).

У коротких ссылок Travelpayouts есть документированный способ менять `sub_id`.
Это не универсальное правило для любых ссылок/провайдеров: подтвердите тип вашего URL.
[SubID коротких ссылок](https://support.travelpayouts.com/hc/en-us/articles/12729746524050-How-to-dynamically-change-SubID-in-short-affiliate-links).

Разработчику нужны: исходный URL, готовый affiliate URL, точный host первой ссылки,
program/Project/marker, поддерживаемый SubID. Проверенное имя хоста без `https://` и пути
записывается в `AffiliateProgram.allowed_hosts`, имя SubID — в `tracking_param` этой же программы.
Глобальные `AFFILIATE_ALLOWED_HOSTS` и `AFFILIATE_TRACKING_QUERY_PARAM` больше не включают переходы.
Настройки вносятся через защищённый admin API; пошаговый порядок — в [operations.md](operations.md).

**Готово:** есть рабочий образец ссылки, который открывает ожидаемую страницу.
I08–I10 проверены локально; теперь проверяем настоящий переход с сайта через `/go` и запись клика.
Сгенерированная ссылка сама не заполняет DealComponent в нынешнем приложении.

## 10. Что написать поддержке, если неясны доступы

В Help Center используйте Submit a request. Заполните пример, затем отправьте его сами.

```text
Subject: HopTrip: cached flight data and affiliate links for a new Polish website

Hello,
I am building HopTrip, a Polish travel discovery website: <ACTUAL_URL>.
The project is new and currently has <ACTUAL_TRAFFIC> visitors.
Project ID: <PROJECT_ID>. Selected program: <PROGRAM_OR_NOT_SELECTED>.
Our planned channels are website content and organic search.

Please confirm:
1. Which flight program can accept this Project and Polish traffic?
2. May we display cached Data API prices and retain observations for price-history comparisons?
3. Which current endpoint, market and currency settings should we use for WRO/Poland and PLN?
4. Which permitted link format opens the corresponding flight search and supports SubID?
5. What price timestamps, attribution rules and promotional restrictions apply?
6. Which reports/API/export expose booking status, SubID and commission for this program?

We are asking about cached data for a new website, not assuming live Search API access.
Thank you.
```

Прикладывайте URL проекта и текст ошибки без токена. Сохраните номер обращения,
ответ и дату следующей проверки в своей заметке. Если программу не одобрили,
зафиксируйте причину и условия повторной заявки; продолжайте внутреннюю разработку.

## 11. После доступов: публикация и проверка

1. Убедитесь, что обязательные задачи данных, affiliate policy, CTA и защиты из внутреннего
   плана завершены. Доступы не заменяют эти изменения.
2. На сервере заполните `.env.production`. Сопоставление основных полей:

   | Поле | Откуда взять |
   | --- | --- |
   | `HOPTRIP_DOMAIN` | Выбранный hostname, без схемы и пути |
   | `HOPTRIP_EDGE_NETWORK` | Реальная сеть существующего proxy, если используется shared-proxy |
   | `ACME_EMAIL` | Ваш действующий email |
   | `POSTGRES_PASSWORD`, `ADMIN_TOKEN` | Разные длинные случайные секреты из менеджера паролей |
   | `TRAVELPAYOUTS_API_TOKEN` | Шаг 7 |
   | `CORS_ORIGINS` | Ваш HTTPS origin; production Compose задаёт его из домена |

   Host, SubID и готовая ссылка задаются в программе/компоненте через admin API,
   а не глобальными переменными окружения. APPROVED устанавливается только после
   фактического одобрения программы в вашем кабинете.

3. Выполните соответствующий вариант развёртывания из [operations.md](operations.md).
   Для VM с действующим proxy нужны все три Compose-файла; два отдельных proxy не должны
   одновременно занимать одни host-порты.
4. Проверьте снаружи HTTPS-сайт и `/health/ready`. Выполните один ingestion, затем включите
   worker с интервалом, соответствующим подтверждённым ограничениям API.
5. Пройдите WRO → реальная сделка → цена/даты → партнёрская кнопка. Проверьте внутреннюю
   запись клика и доступный отчёт сети по SubID. Не покупайте билет только ради проверки ссылки.
6. Выберите место резервных копий вне VM, периодичность и retention. Выполните отдельный
   restore drill по подготовленной процедуре, не поверх единственной рабочей базы.
7. В кабинете партнёра заполните необходимые сведения для выплат; сохраните доступный
   способ, порог и периодичность. Конкретные требования берите из вашего кабинета.

**Готово:** есть реальный путь от цены до отслеженного перехода, работает обновление,
понятно, как получить отчёт о бронированиях и восстановить данные.
