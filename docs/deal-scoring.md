# Оценка предложения flight-v3

Обновлено 2026-09-27. Индекс помогает сравнивать предложения по цене и имеющимся
данным; он не оценивает авиакомпанию, комфорт, безопасность или вероятность покупки.
Веса и пороги — явные продуктовые правила, не статистически откалиброванная модель.

## Расчёт

Три независимых вклада, сумма максимум 100:

| Критерий | Максимум | Правило |
| --- | --- | --- |
| Цена относительно медианы | 60 | `0.6 × clamp(50 + 100 × (median - price) / median, 0, 100)` |
| Объём истории | 25 | `25 × min(sample_count / 30, 1)` |
| Свежесть | 15 | `15 × clamp(1 - age_hours / 48, 0, 1)` |

Ценовая формула применяется при корректной медиане и минимум 5 наблюдениях.
Иначе цена получает явно обозначенные нейтральные 30/60, а статус — PROVISIONAL.
Некорректная/отсутствующая медиа́на обнуляет используемый объём истории. Неизвестный
или будущий timestamp, либо истёкший expires_at дают 0 за свежесть. Отсутствие
expires_at не означает отсутствие наблюдения: свежесть считается по observed_at.

Каждый вклад округляется Decimal ROUND_HALF_UP до 0,1; складываются именно эти
видимые числа; итог округляется ROUND_HALF_UP до целого. Никакого float в v3.
Пример, не предложение: price=330, median=400, n=24, age=24h:
`40.5 + 20 + 7.5 = 68/100`.

Цена учитывается один раз. Бонус за неизвестное удобство исключён. Комиссии,
багаж, пересадки, расписание и условия тарифа не входят в оценку.

Сохраняются score_version=flight-v3 и score_components.breakdown: вклады/максимумы,
сумма до округления, размер выборки, цена/медиана/знаковая разница, observed_at,
calculated_at и SOURCE/FIRST_SEEN. Время last_verified_at не заменяется временем
повторного скачивания того же кеша. FIRST_SEEN означает известный возраст нашей
записи, а не известную свежесть цены у продавца.

## API и интерфейс

Каталог и detail возвращают score_explanation из одного сериализатора. Проверка
суммы защищает от выдачи объяснения, не соответствующего сохранённому числу.
Чтение не пересчитывает оценку: сортировка и объяснение используют один снимок.
Свежесть в окне явно относится к времени расчёта; очередной pipeline обновляет
снимок. Общий read-time guard по-прежнему скрывает истёкшие/старые предложения.

В карточке оценка — отдельная ссылка, открывающая native dialog по нажатию/Enter.
Есть явное закрытие, Escape, возврат фокуса и удержание фокуса внутри окна.
Hover даёт короткую подсказку; полное пояснение доступно на сенсорном экране.
Ссылка также имеет адрес `/deals/{slug}#score`, который можно открыть отдельно,
например Ctrl+нажатием. Там расчёт отрисован сервером. Полная работа сайта без
JavaScript не заявляется: существующий Next.js loading/streaming требует скриптов.
Цена, количество наблюдений, возраст, ограничения и арифметика видны в пояснении.
PROVISIONAL отображается как «Ocena wstępna» уже в карточке.

## Совместимость и выпуск

Миграция БД не требуется. Действующие записи v2 не переписываются на чтении:
показываем их прежние вклады (35/20/15/15/15) с отметкой предыдущей методики.
Для v2 сохраняется историческое округление round(float), включая ties-to-even.
Если исходные компоненты отсутствуют/повреждены или сумма не соответствует итогу,
статус UNAVAILABLE сообщает, что достоверно восстановить расчёт нельзя.

После установки новой версии очередной успешный pipeline пересчитает свежие
предложения на v3. На переходе старые и новые индексы не полностью сопоставимы;
после первого цикла проверить score_version у активных предложений. Применение
изменений к production в рамках локальной реализации не выполняется.

## Ограничения сравнения

Историческое сравнение: один data provider, origin/destination, FLIGHT, месяц вылета
и длительность. Для one-way длительность NULL и отдельный уникальный bucket.
Наблюдения могут включать текущую цену, коррелированные значения и разные тарифы;
30 записей не означают 30 независимых продавцов или гарантированную точность.
При отсутствии baseline сохранённая скидка 0, оценка предварительная. Это flight-only,
отели и непроверенные дополнительные расходы не подмешиваются.

Модерация: GET /api/v1/admin/deals?q=...; PATCH /api/v1/admin/deals/{id}
с is_visible/is_featured. Все действия требуют X-Admin-Token.
Пересчёт не меняет редакторские флаги.
