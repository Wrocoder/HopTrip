# Уточнение цен выбранных поездок — 28 октября

Статус: опубликовано на https://hoptrip.pl через PR #20, выпуск 6dd9cbc370d61efa9379d637ff09b0ff72533802.

Исправлены две подтверждённые причины расхождений:

- Источник запрашивал market=pl, хотя партнёрский переход открывает aviasales.com.
  REST и GraphQL теперь используют единый TRAVELPAYOUTS_MARKET=us; валюта остаётся PLN.
- Общая подборка дешёвых направлений не гарантирует возврат обновившейся цены уже
  опубликованного билета. Добавлено отдельное обновление точных дат существующих поездок.

До изменения, 14:17 UTC: у Милана 4–9 ноября сохранено 184 PLN, но точный запрос
уже отдаёт 249 PLN (GraphQL 248,8). Для Стокгольма 27–30 ноября польский рынок
возвращает 133 PLN, американский — 141 PLN (GraphQL 141,31); ранее в полностью
загруженной выдаче aviasales.com владелец проверил 142 PLN.
[Снимок источников](price-fix-20261028/markets-before.json) получен без изменения записей и истории.

## Поведение

В каждом цикле перелётов проверяются до 40 групп «аэропорт → город + точные даты».
Проверка выполняется перед общей загрузкой, затем пересчитываются предложения,
статистика и партнёрские ссылки. Для вылетов в ближайшие 7 дней интервал проверки
минимум 1 час, в пределах 30 дней — 4 часа, дальше — 12 часов. Фактическая
проверка выполняется в ближайшем штатном цикле: на production явно задано
PIPELINE_INTERVAL_SECONDS=7200, то есть каждые два часа. Эти интервалы определяют
повторный запрос кеша и не являются обещанием свежести цены. События — раз в
сутки в 06:00 Europe/Warsaw.

Для замены цены нужны полные ограниченные ответы обоих API и совпадение всех
сегментов туда и обратно: аэропорты, UTC-время, перевозчик и номер рейса.
Сохраняются исходные id/slug; обновляется выбранный билет в партнёрской ссылке.
Из нескольких подтверждённых тарифов выбирается минимальный. Общая загрузка также
больше не перезаписывает дешёвый тариф последним дорогим дубликатом.

Уточнённая цена защищена от перезаписи общим списком дешёвых направлений.
Её может заменить следующий подтверждённый адресный снимок. При ошибке,
усечении, отсутствии билета или неизвестном обратном маршруте цена не меняется;
срабатывает прежний TTL. Отсутствие в кеше не объявляется отсутствием мест.

Повторная цена сохраняет первое наблюдение и срок окончания. Даже при возврате
ранее встречавшейся цены дата не обновляется автоматически. История сохраняется.
Проверенные снимки и время попытки хранятся в route_details; новых миграций нет.
Команда ручного обновления использует общую блокировку со штатным загрузчиком:

~~~sh
python -m app.jobs.refresh_flight_prices --offer-id 3827 --offer-id 3719
~~~

Без --offer-id действует обычная очередь свежих предложений и бюджет 40 групп.
Настройка FLIGHT_PRICE_REFRESH_GROUPS доступна API/worker через Compose.

## Проверки

Регрессионные тесты покрывают увеличение/уменьшение цены, оба направления и
смену аэропорта/номера/времени обратного рейса, несколько тарифов, усечённый
REST, повтор страниц GraphQL, ошибки API, сохранение истории/срока и защиту
от старой общей выдачи. Отдельно проверен возврат ранее наблюдавшейся цены.

## Ограничения

Это [официальный Data API с кешированными результатами пользовательских поисков](https://support.travelpayouts.com/hc/en-us/articles/203956163-Aviasales-Data-API),
а не проверка наличия мест у продавца. Рыночный параметр и валюта независимы.
[Search API](https://support.travelpayouts.com/hc/en-us/articles/210995808-How-to-get-access-to-the-Aviasales-Search-API)
требует отдельно одобренного доступа; в конфигурации проекта подтверждены только
партнёрские ссылки и Data API. Поэтому абсолютное совпадение с оформлением заказа
не гарантируется. Прежние сроки 6/24/48 ч сохраняются: сокращение всего каталога
до 6 ч скрывало бы около 90% проверенной выборки.

Полная проверка физического телефона и пользовательские уведомления остаются
отложенными владельцем. Этот выпуск их не запускает.

Локально: 602 теста API успешно; 7 PostgreSQL пропущены без локальной БД. Ruff и mypy (93 модуля) успешно. CI PR и main, включая PostgreSQL, 78 web unit-тестов и сборку, успешны.
